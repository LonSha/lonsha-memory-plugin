## M-O1 · 真实宿主下的会话身份写入闭环（P0，规模 M–L）
**真实需求**：`StorageManager.save(chatId, data)` 的底层边界探针已证明「宿主处于 B 时调用 save('A') 会写 B 的 metadata」；生产调用方的栅栏是否让这条路径可达，**尚未端到端证明**。

**工作**：
1. 逐调用核对：租约捕获、队列延迟、紧急备份 await、切聊、宿主保存出口。
2. 写入前与**每次 await 之后**核验目标 chat / branch / revision。
3. 有真实「按目标会话保存」出口则明确委托；否则拒绝或延期旧会话批次，绝不写当前 metadata。
4. 批次 envelope 的 revision 用 `curRev`（非循环外 `currentRev`）；按批次区分 `queued / confirmed / failed / partial`。
5. 不得以「任一批成功」代表整队列成功。

**验收**：
- A→await→B、A/B 队列交错、宿主 `saveChat=false`、异 chat `load`、同 chat 合并，五种序列全覆盖。
- 不匹配的目标 metadata **不改变、不推进确认**。
- 批次身份、revision 与确认回执来自同一批。
- 真宿主路径至少有一批可复现证据（与 M-O2 合批）。

**复用**：既有 coalescing、stale-guard、epoch —— 不重造存储引擎。

## M-O2 · 真实浏览器与真宿主的控件交互回归（P0，规模 L）
**真实需求**：v3.287.0 交付的是零依赖 DOM shim 下的交互逻辑切片。**真浏览器按 manifest 顺序装载生产模块**、真实点击 / 滑块 / 输入 / 焦点 / 窄屏、重开保留，全部**未执行**。

**工作**：
1. 真实浏览器按 `manifest.extra_js` 顺序装载生产模块。
2. 流程：首次启动 → 设置 → 编辑保存 → 重开 → 检索 → 检查点预检 → 诊断 → 修复预览。
3. 控件面：展开、滑块、输入、焦点、窄屏（320px）。
4. 真宿主：生成、楼层重生成 / 删除、切角色、与手机插件双扩展共装。
5. 核心面板**空态与有数据**两组都覆盖。

**验收**：
- 控件有 DOM、可见、可操作、改变正确状态、重开保留。
- 每个流程记录版本与宿主 / fixture 标记。
- 加载缺失（真缺陷）与抽取器漂移（结构漂移）**两者不混**。
- 模块缺席不冒充空账；**未执行不算通过**。

**依赖**：M-O1 的存储行为。

## M-O3 · 预算、裁剪与注入回执统一为单一真源（P0/P1，规模 M）
**真实需求**：真裁剪已记录 `keptIdxInAll` 与硬截断 spans，但 `_lastBudgetStats` 仍以 `full.includes(b)` 反推 keptBlocks，`cost-forecast` 同法。重复文本、互为子串、半段裁断都会让**显示与真裁剪回执不一致**。

**工作**：
1. 以一次真实裁剪 trace 为唯一来源，导出聚合数、逐块归因与预测。
2. 区分六类量：候选字符 / 载荷字符 / 被丢块字符 / 裁剪减少字符 / 预算溢出字符 / **未知范围**。
3. 未知保留 `null` 与来源，**不倒推「成功」**。
4. 常驻块超量时显式报告原因与选择，不静默裁断关键事实。
5. 容量口径必须含首尾说明、分隔符与 token 口径；相关性 / 时效策略先排序再按可用容量选。

**验收**：
- 同文两份只保一份，计数就是一份；子串块与半块各有真实状态。
- 诊断、快照、cost-ledger、forecast、策略对照对同一 trace 一致。
- 删 trace 的负控制让「未知」可见，**不得变成「全部留下」**。
- 禁用条目不计入实际注入；非激活内容不计。
- 零候选 / 只有常驻 / 超长单块 / 刚好卡线 / CJK+ASCII 混合均可测。

## M-O4 · 长对话的规模、缓存与归档实效（P1，规模 L）
**真实需求**：缓存、双 hash、snapshot checkpoint、archive-shift、休眠与生命周期门都已存在；缺的是**组合运行后的实效与成本**读数。

**工作**：
1. 1000 / 5000 / 10000 楼 × 多角色 × 多秘密 × 多分支压力序列。
2. 量召回、投影、存档、诊断的 p50 / p95、扫描量、快照字节、后半段堆斜率。
3. 按实际热点做增量索引、版本失效与派生缓存。
4. 区分活动索引 / 归档证据 / 有界诊断；归档后仍能定位出处。

**验收**：
- 同输入真命中缓存；改楼 / 切聊 / 恢复**真失效**。
- 规模上升不静默漏掉可用记忆。
- 归档或 tombstone 不抹掉审计 provenance。
- 前后台恢复不突发全量重算。
- 先记录新基线，再定目标设备预算。

## M-O5 · 质量评测升级为留出集与端到端（P1，规模 L）
**真实需求**：55 样本 / 12 类与 known-gap 归零已交付。固定样本满分**可能来自词表覆盖充分**，不能据此宣布真实剧情质量满分。

**工作**：
1. 在现固定集外建**留出集**与多轮状态序列：paraphrase、同名异人、伪装身份、闪回 / 当下、事实换代、秘密、重生成、跨会话。
2. 指标分开计：错召回率、秘密泄露率、旧事实压过新事实率、来源正确率、无答案时的如实拒绝率。
3. 有真模型条件时，测提取 → 写入 → 召回 → 实际请求载荷 → 生成。
4. 模型输出与确定性内核**分报告**；人工标注保留原文依据。

**验收**：
- 新增能力在不改期望集的前提下提升。
- 无答案样本不得靠扩召回数量得分。
- 泄密等禁入指标单独计，**不被平均命中率抵消**。
- 留出集不得边测边扩词后仍称「独立泛化验证」。

## M-O6 · 事实版本、冲突与撤回的状态统一（P1，规模 M–L）
**真实需求**：事实版本、supersede、stale guard 与修复链都已存在，但真实使用中最易出错的是「新事实已写入，旧投影 / 关系 / 召回仍在使用」。

**工作**：
1. 统一事实状态：`active / superseded / revoked / disputed / unknown`。
2. 明确时间有效范围与写入 revision。
3. 状态变化须传播到摘要、图谱、时间线、召回与缓存。
4. **禁止只改展示层**掩盖源数据未修复。

**验收**：
- 新事实优先，旧事实仍可追溯。
- 撤回后不再进入角色生成载荷。
- 冲突不按「更新时间更晚」自动覆盖。
- 状态变更幂等且可回读。

## M-O7 · 重复实现、依赖与历史测试迁移（P1，规模 M–L）
**真实需求**：`index.js` 已回到 15328 行（超过旧里程碑线）。继续追行数会「搬走代码却保留两套维护面」—— 真实成本在 barrel 副本、`bindDeps`、缺席 fallback 与几十个源码抽取套件。

**工作**：
1. 按真依赖与调用密度盘点副本，**不按域拆**（沿用既有否决结论）。
2. 先把关键历史抽取测试迁为「真实模块装载 + 宿主夹具」，再收紧可移除副本。
3. 保留 IIFE / CJS、manifest 装载顺序与独立运行能力；按方法名核对 fallback。
4. 成员级提取只处理明确热点。

**验收**：
- 每批减少实际重复实现或夹具耦合，**真实行为证据不减**。
- `bindDeps` 全量注入与失败部分均可观察。
- 扫描器与负控制副本同步跟真源迁移。
- 不得用更新 baseline 洗掉断言。

## M-O8 · 隐私、秘密与跨项目隔离审计（P1，规模 L）
**真实需求**：秘密账本、角色知识、手机事实与跨分支机制越完整，越需要证明**坏数据不会越权注入**。

**工作**：
1. 审计秘密在查询、召回、诊断、导出、手机桥、模型载荷六条路径上的传播。
2. 严格区分：作者可见 / 玩家可见 / 角色可知。
3. 检查同名异人、伪装身份、同一角色不同宇宙。
4. 加入跨会话、跨分支、跨项目负控制。

**验收**：
- 未获知的秘密不进入角色生成上下文。
- A 分支秘密不出现在 B。
- 诊断可显示「存在但不可用」，不得直接泄露正文。
- 导出包按知识范围过滤。

## M-O9 · 当前事实、门禁与文档自动同源（P1，规模 M）
**真实需求**：文档读数真实性门（D1~D9）与计划陈旧标记已交付，但「当前版本 / 装载面 / 测试数 / 审计数」仍需人工复算，抬版与增删模块时容易漂移。

**工作**：
1. 当前能力表由 manifest、测试发现、模块注册表与门禁输出**自动生成**。
2. 历史研究一律标快照版本，不再作为当前待办。
3. 门禁分档记账：`npm test` / `npm test -- --audit` / 定向套件 / 真宿主验证。
4. 建立测试耗时热点读数（沿用 `test_cost_readings.json` + 重绑工具）。

**验收**：
- 当前版本、人读索引与机器装载面三者一致。
- 未实跑的全量明确标注待验；未知不报 0，未执行不报通过。
- 已交付条目不再列为下一步；新提案不得复活旧研究的「当时未做」。
- 干净检出可重建同一份状态报告。
