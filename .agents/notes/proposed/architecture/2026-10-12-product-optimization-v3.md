# Agent Note: lonsha-memory-plugin 第三期产品主线·优化提升（九项）

Status: proposed

## Problem

用户要求把重心从守卫、台账和抬版转回项目主题。本计划基于 v3.319.0 / `b36c73a` 的代码侦察与定向探针，不沿用旧计划的完成勾选。这里交付的是计划，不是已实现功能；没有执行真实模型/浏览器体验验收。

## Proposal

共九项，编号 M3-O1 至 M3-O9。P0优先解决核心正确性，P1完成主要体验，P2扩展玩法；M/L为中/大工作包，不是工时承诺。每项必须产生玩家可见收益，不以新增门禁或多写文档作为完成标准。

### M3-O1 · 召回排序更贴合当前剧情（P0 / L）

- **现状与依据**：index.js::hybridMerge 已混合召回并接rerank，ai-select.js::scoreEntry 有字面权重；不是新增向量检索。
- **具体增量**：优化候选融合的尺度、语义重复与角色/事件覆盖；当前任务相关事实优先，老而关键的约定不被近况淹没；复用现有rerank与可选模型。
- **用户验收**：固定预算下比较相关事实覆盖、重复率、旧事实误用与无答案误召；保留既有留出集，新场景另留未调参样本；收益必须体现为更好的请求内容。
- **依赖与复用**：M3-O2/O3/O9；先测候选组成，再定权重，不预承诺百分比。

### M3-O2 · 图谱候选不再提前损失关键信息（P0 / M）

- **现状与依据**：unified-recall.js::nodeToCandidate 把内容压到200字、secondary短语只取8条；候选层损失发生在后续评分前。
- **具体增量**：候选索引保留身份/时间/关系/结果关键字段与完整源ref；展示摘要和检索文本分离；选中后按任务预算提取证据句，保护否定和数额。
- **用户验收**：超过200字才出现的关键结论仍可被检索；完整原文不全量注入；同一事件多节点不会重复占预算；不同事件不因同开头合并。
- **依赖与复用**：复用unified-recall/ai-select；给 M3-O1 与 R3-O2 供更好的证据。

### M3-O3 · 同名、代称与伪装身份的时段解析（P0 / L）

- **现状与依据**：entity-semantic.js 已有唯一名字/别名解析和显式绑定；index.js 已接实体表与 aliasQueryExpansion。现有实体shape为id/kind/name/aliases。
- **具体增量**：补别名的项目/分支/有效时段与称呼者范围；“她/老师/珞珈”结合在场与最近指代生成候选，歧义不硬合并；已揭穿身份不反向泄露到旧楼。
- **用户验收**：同名异人与不同年龄版本不混；伪装前后查询各按当时明面身份；人工绑定可撤回；手机和主聊天采用同一实体映射。
- **依赖与复用**：M3-O9；与 R3-O1 对接ID。

### M3-O4 · 长篇摘要保住承诺、转折和关键原话（P0 / L）

- **现状与依据**：stm-ltm.js 有40条STM/24条LTM滚窗与摘要尾部裁剪；memory-core.js 已有分层摘要/卷摘要与回源。
- **具体增量**：把已存在的摘要层级用于关键事实保留与可检索归档；合并时保留未结约定、状态转折、数字和必要原话；以差量更新减少反复摘要漂移。
- **用户验收**：数十次巩固后早期未结约定仍可查；过时状态不当现状；超窗不简单无限扩容；原文缺失时明确不可恢复，不能伪称无损。
- **依赖与复用**：M3-O2/O9；复用SummarySystem/STM-LTM，不增加第二套长期库。

### M3-O5 · 提取节奏从固定周期转为剧情变化驱动（P1 / L）

- **现状与依据**：extraction-cadence.js 按类型 seq % everyN；smart-trigger.js 已有关键词、标点、角色切换等门控。
- **具体增量**：联合结构化状态变化与待补范围安排提取：身份/承诺/物品转移及时抽，寒暄批处理；重生成只补受影响段；用户可选质量优先/均衡/低消耗。
- **用户验收**：关键事件即使落在非周期楼也被提取；连续寒暄不每次全类型请求；错过的楼不消失；报告真实调用量与事实召回质量，不以省调用数单独验收。
- **依赖与复用**：M3-O3/O4；沿用smart-trigger与cadence，不添第二调度器。

### M3-O6 · 大型记忆库查询即时响应（P1 / M）

- **现状与依据**：evidence-query.js::query 每次universeOf→遍历→sortRows→分页；单账扫描上限20000；已有分页和完整度说明。
- **具体增量**：按revision缓存可复用投影，建立角色/来源/楼层轻索引；分页不反复物化全部；大查询协作式让出与取消；范围上限给可继续查询的入口。
- **用户验收**：万条事实库下翻页/换筛选不冻结界面；修改一条只更新受影响索引；结果与原逻辑对照一致；缺失范围仍可见。
- **依赖与复用**：M3-O3；没有浏览器测量时只报告算法与Node数据，不能报手机帧率。

### M3-O7 · 提取反馈给出可比较的修正方案（P1 / L）

- **现状与依据**：extract-feedback.js::suggest 已记录五类问题，但 apply.key/from/to 固定null，只给目标面，compare/holdout由调用方提供。
- **具体增量**：基于真实错例生成有界配置候选和局部重提取预览；显示修前/修后事实与预算差，用户确认再应用；撤回配置与撤回事实明确分开。
- **用户验收**：标记“错角色”后能看到候选实体映射及影响；标记漏记能只重提该段；不靠一句“已改善”自证；默认不自动改参数。
- **依赖与复用**：M3-O3/O5；复用反馈、projection对照与repair-settle。

### M3-O8 · 记忆控制中心从技术表变成可操作资料页（P1 / M）

- **现状与依据**：memory-center.js 已有筛选、分页、保存条件与actionButtons；rowsHtml 主要展示ledger/floor/status/ref及截短title/detail。
- **具体增量**：用人物/事件/时间资料页组织结果，侧栏看完整证据与修订链；批量保留/隐藏生成/撤回有影响预览；进出详情保留筛选和页码。
- **用户验收**：普通用户能完成找事实→看原文→纠错→确认结果，不需认识内部账名；受限正文保持遮蔽；批量操作失败保留未完成选择。
- **依赖与复用**：M3-O6；复用已有center/lifecycle/repair，不重建控制中心。

### M3-O9 · 当前与当时的记忆时态一致（P0 / L）

- **现状与依据**：fact-version.js 已有有效区间，fact-state.js 已有五态，story-clock-parse.js 与世界钟读面已在；evidence-query主要以楼层/revision筛选。
- **具体增量**：统一查询意图中的“现在/当时/闪回之后”；按剧情有效时间而非录入新旧选择事实；矛盾时间保留候选及原因，避免闪回覆盖当前状态。
- **用户验收**：“她当时住哪里”和“现在住哪里”可得不同正确答案；后补录旧事件不覆盖现状；时间未知不补现实日期；时段映射用于实际注入。
- **依赖与复用**：复用事实区间/剧情钟；与 M3-O3/O4 联合交付。

## Alternatives considered

- **继续强化守卫与台账**：能减少工程回归，但不能让用户聊得更像、记得更准。本轮不占任何名额，只修阻塞对应功能的最小问题。
- **把第二期未勾项重新列一遍**：成本低，但当前已有后续实现，容易重复造轮子。旧计划按历史快照保留，本轮以真代码和增量边界接管排序。
- **重建底座或新增一批独立App/账本**：可快速增加功能数量，却扩大分裂状态和维护成本。优先在现有入口、owner与存储上连成完整用户流程。

## Acceptance criteria

1. 每项先保留同场景基线，随后证明具体操作/输出改善；正确性用定向测试，体验用真浏览器/宿主，模型质量用固定预算与未参与调参的样本，三类证据不能互代。
2. 复用已有测试与审计；不为每个计划编号加一个守卫，不把通过测试数当产品收益。发布前按现有仓规执行所需检查；计划阶段只作相关检查。
3. 建议功能实现与体验打磨占实际投入至少80%，必要测试/接线/记录通常不超过20%；这是分配目标，不得为达比例省掉数据安全验证。安全故障可暂停，但不得顺势开启泛化审计项目。
4. 默认不增加LLM调用；确需模型的步骤按需、可取消、有预算预览。禁止未经确认执行真实外部发布/转账。
5. 现有会话/分支隔离、事实owner、备份与权限仍是约束；新接口应先服务真实消费点，再同步既有登记。

## Risks

- 本轮代码阅读和合成探针不等于用户实机故障发生率。除证据文档中的实测外，其余是以现实现限制为依据的改进提案；开工先跑目标旅程，不成立则缩减/撤项，不硬凑实现。
- 大工作包不可只交内核后就勾完成；需包含真实入口、操作、持久化/请求效果与对应验收。无服务或宿主能力须明确保留未验收项。
- 跨仓同名条目由owner区分：记忆侧负责事实/查询，手机侧负责展示/交互，不把同一次桥登记重复计成两个成果。
