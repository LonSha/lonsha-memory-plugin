# Agent Note: LonSha 记忆引擎优化提升计划（v3.271.0 核实基线）

Status: proposed

## Problem

引擎已有丰富账本、召回、注入回执、修复与分支机制，当前主要风险是这些机制在真实宿主组合运行时失效、部分读数仍凭文本反推，以及用户只能看诊断而不能完成处置。

基线为 2026-10-04 v3.271.0，HEAD `1a0ba36`，起手工作区干净。`index.js` 1011877 字节 / **13555 行**，251 个 `*.test.mjs`，`manifest.extra_js` **79 项**（当前根目录 JS 80 件，入口与额外装载面须分开计）。本轮实跑 UI 门：8 个入口调用 0 异常、设置页 1959 个 DOM 元素 / 75 个带 id 控件；版本守卫问题 0。55 样本 / 12 类剧情评测的三阶段命中与机制守卫读数均为 1.0，known-gap 为空。以上是定向证据，不是当前全量验收，也不证明真实模型在长对话里的质量满分。

## Proposal

### O1 · 保存与加载的会话身份保护（P0，规模 M–L）

依据：`memory-organs.js::StorageManager.save(chatId,data)` 按 chatId 合并队列，但实际写入使用执行时的 `SillyTavern.getContext().chatMetadata`，未在这一层核验目标会话。本轮真类＋合成宿主探针调用 save('A')，宿主处于 B，结果 B 元数据出现 `chatId:'A'` 且返回 true / confirmed A。load(chatId) 同样只读取当前上下文元数据，需一并审计。该探针证明底层边界不完整；生产调用方栅栏是否使这条路径可达，尚需端到端验证。

工作：逐调用核对租约捕获、队列延迟、紧急备份 await、切聊和宿主保存出口。写入前与每次 await 后核验目标 chat/branch；有真实按目标保存出口则明确委托，否则拒绝/延期旧会话批次，绝不能写当前 metadata。批次 envelope 的 revision 使用 `curRev`，而非循环外 `currentRev`；按批次区分 queued/confirmed/failed，不能以任一批成功代表整队列成功。

验收：A→await→B、A/B 队列交错、宿主 saveChat=false、异 chat load、同 chat 合并全部测试；不匹配的目标 metadata 不改变、不推进确认；批次身份、revision 与确认回执来自同一批；生产路径同样有可重现证明。复用现有 coalescing、stale-guard 与 epoch，不重复造存储引擎。

### O2 · 从入口渲染扩到真实用户操作（P0，规模 L）

依据：v3.271.0 已修设置空白并建立 U1–U5 零依赖运行时门；这个任务已经交付，下一步是控件行为、持久化、排版和完整装载。DOM shim 不会证明宿主 CSS 或浏览器点击有效。

工作：真实浏览器按 manifest 顺序加载生产模块，走首次启动→设置→编辑保存→重开→检索→检查点预检→诊断；测展开、滑块、输入、焦点与窄屏。真实 SillyTavern 再跑生成、楼层重生成/删除、切角色、两插件共装；核心面板空态与有数据都覆盖。

验收：控件有 DOM、可见、可操作、改变正确状态且重开保留；每个流程记录版本与宿主/fixture；加载缺失为真缺陷、抽取器漂移为结构漂移，两者不混。模块缺席不冒充空账，未执行不算通过。依赖 O1 的存储行为。

### O3 · 预算裁剪的可执行契约（P0/P1，规模 M）

依据：常驻块被明确保护，所以常驻超量不能一律判 bug。为排除这个前提，本轮使用三块无常驻内容、budget=200：balanced **218 字符**（封装尾与分隔符漏计）、relevance **471**（至少三块/前 60% 规则未按容量选取）、recency **200**（走硬截断）。此前带常驻样本的 397/900/397 读数不能用来宣称三策略均失效。

工作：约定默认软预算＋关键事实保护，补明确硬上限模式与溢出原因。容量必须包含首尾说明、分隔符与 token 口径；相关性/时效策略先排序再按可用容量选，不以比例代替预算。常驻自身超量时显式报告原因与选择，不偷偷裁断关键事实。保持未开启硬上限的历史兼容，并同步 cost-forecast/预演。

验收：零候选、只有常驻、超长单块、同文重复、刚好装下、CJK/ASCII/混合文本均可测；无保护溢出时不超过约定上限；保护溢出时回执明示；tokenizer 真值与估算分开。临界值测试必须能抓住封装漏计。

### O4 · 注入与预测完全消费过程回执（P1，规模 M）

依据：真裁剪已记录 `keptIdxInAll` 与硬截断 spans，但 `_lastBudgetStats` 仍用 `full.includes(b)` 算 keptBlocks，`cost-forecast` 也按 includes 反推。重复文本、互为子串、半段裁断会造成显示与真裁剪回执不同，属于已交付机制剩余消费者的口径迁移。

工作：统一由生产裁剪 trace 导出聚合数、逐块归因和预测；未知保留 null 与来源，不倒推“成功”。区分候选字符、载荷字符、被丢块字符、裁剪减少字符、预算溢出字符；保持旧字段兼容，语义改变必须迁移/标版。

验收：同文两份只保一份，计数就是一份；子串块和半块各有真实状态；诊断、快照、cost-ledger、forecast 对同一 trace 一致；删 trace 的负控制让未知可见，不得变成“全部留下”。依赖 O3。

### O5 · 长对话的规模、缓存与归档治理（P1，规模 L）

依据：已有 cacheHit、双 hash、snapshot checkpoint、archive-shift、休眠与生命周期门；不能再建议从零加缓存或归档。重点是组合运行后的实效与成本。

工作：1000/5000/10000 楼、多角色、多秘密与多分支压力序列，量召回/投影/存档/诊断的 p50/p95、扫描量、快照字节与后半段堆斜率。按实际热点增量索引、版本失效和派生缓存；检索升温不能改成串会话共享结果。区分活动索引、归档证据与有界诊断，归档后仍能定位出处。

验收：同输入真命中缓存，改楼/切聊/恢复真失效；规模上升不静默漏可用记忆；归档或 tombstone 不抹掉审计 provenance；UI 大列表可滚动，前后台恢复不会突发全量重算。先记录新基线，再定目标设备预算。

### O6 · 质量评测升级为端到端与留出验证（P1，规模 L）

依据：55 样本 / 12 类、known-gap 归零已经交付。固定样本满分可能来自词表充分覆盖；不能据此宣布真实剧情质量 100%。

工作：在现固定集外建留出集与多轮状态序列，保留 paraphrase、同名异人、伪装身份、闪回/当下、事实换代、秘密、重生成与跨会话。测错召回率、秘密泄露率、旧事实压过新事实、来源正确、未答时是否如实拒绝；有真模型条件再测提取→写入→召回→实际请求载荷→生成。模型输出与确定性内核分报告，人工标注依据保留原文。

验收：新增能力在不改期望集的前提下提升；无答案样本不会靠扩召回数量得分；泄密等禁入指标单独计不被平均命中率抵消。留出集不能拿来即时扩词后还称独立泛化验证。

### O7 · 外移模块依赖与历史测试减负（P1，规模 M–L）

依据：<15000 行目标已达成，当前 13555 行。barrel 副本、bindDeps、缺席 fallback 与几十个源码抽取套件扩大后续改动成本；继续追行数会搬走代码却保留两套维护面。

工作：按真依赖与调用密度盘点副本，先将关键历史抽取测试迁为真实模块装载＋宿主夹具，再收紧可移除副本。保留 IIFE/CJS、manifest 装载顺序和独立运行；按方法名核对 fallback。成员级提取仅处理明确热点，沿用已否决“按域拆”的结论直到新证据足以改变它。

验收：每批减少实际重复实现/夹具耦合，真实行为证据不减；bindDeps 全量注入及失败部分可观察；扫描器与负控制副本同步跟真源迁移；不能用更新 baseline 洗掉断言。

### O8 · 当前事实、旧决策与门禁成本一致（P1，规模 M）

依据：README 当前版本为 3.271.0，但下方仍有 248 测试、54 审计、extra_js 78 与根模块 79 等旧段；PLAN 基线仍停 3.266.0 且重复旧起手两件。旧研究中的“缺楼层账本/重排序/时间归一”等不能直接当当前缺口。

工作：当前能力表由 manifest、测试发现与真消费点生成；历史研究标快照版本。定向套件、审计与终局全量按既有总控纪律分档；保留 0/1/2 三档与假绿负控制。为测试成本建立热点读数，不减少负控制来换快。把当前提案入口放 PLAN 顶部，历史内容留作交付史。

验收：当前版本、人读索引和机器装载面一致；未实跑的全量明确待验；已交付条目不再列为下一步；新增提案不得把旧研究的“当时未做”复活为当前待办。

## Alternatives considered

继续瘦身到更低行数的强项是入口更易浏览，但当前目标已达成且副本成本高，优先真实装载与依赖治理。仅扩固定集能快速增加样本，难以证明泛化，采用固定回归＋留出集＋长序列。统一硬裁所有常驻块能守住字符上限，却可能丢核心剧情事实，默认保留软预算保护并增加明确可选择的硬上限。用当前 metadata 保存所有排队会话最方便，但会跨会话错写，采用目标身份绑定或拒绝延期。

## Acceptance criteria

建议三批大更新：第一批 O1/O2/O3（存储身份、核心操作、预算契约）；第二批 O4/O5/O6（回执同源、长线成本、质量泛化）；第三批 O7/O8 与首批产品拓展。每批同时报告行为收益、性能成本、定向结果与未覆盖面。

关联[拓展计划](../feature/2026-10-04-expansion-plan.md)。所有后续施工重读当前 HEAD 和最新已交付记录；此文件是核实日快照，不是永久事实。

## Risks

保存边界探针用合成宿主，真实生产可达性需追调用时序；修复底层边界也不能悄悄丢旧会话的排队写入。预算策略变化会影响剧情质量与历史断言，必须同时维护预测消费者。留出评测需要真实标注成本，不能把模型自评当答案。移除副本前必须让历史测试改读生产实现。
