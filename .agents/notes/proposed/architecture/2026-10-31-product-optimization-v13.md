## Problem

当前基线 **v3.431.0**（`index.js:4` `const VERSION = '3.431.0'`，HEAD `150d055`）；
体量 `index.js` 11862 行 / 1218 成员 / `extra_js` 244 项；测试 430 文件 / 审计 68/68。
门禁全绿：`scan_version_guard` 问题 0、`scan_module_consumption` 零未登记孤儿、
`gen_plan_baseline --check` 一致、`scan_ui_panel_drive` W7 四档不同形。

**门槛全绿之后，剩下的真问题是「玩家在面板里能做的事太少了」。** 逐条实测：

1. **面板 25 个视图里，24 个是只读陈列。**
   实测 `settings-ui.js` 的 `viewType === '<view>'` 分支（按分支切段量按钮与动作属性）：
   `memorycenter` 一段 **148768 字符 / 27 个 `<button>` / 31 个 `data-*` 动作属性**，
   其余 24 个分支合计 **约 645~8252 字符不等、绝大多数 `btn=0 / dataattr=0`**。
   逐条读数（分支长度 / 按钮数 / 数据属性数）：
   `volumes 645/0/0`、`graph 667/0/0`、`relations 673/0/0`、`povs 675/0/2`、`vectors 701/0/2`、
   `timeline 751/0/2`、`items 773/0/2`、`deltas 851/0/0`、`diaries 930/0/0`、`status 1135/0/0`、
   `oplog 1179/0/0`、`scene 1269/0/0`、`suspense 1369/0/2`、`xseries 1521/0/1`
   （`xseries` 另一段 11150 字符含 1 按钮 3 属性）、`lockedfacts 1616/0/0`、`conflicts 1649/0/0`、
   `protagonist 2035/0/4`、`report 2519/0/2`、`archive 2583/0/0`、`pulse 4048/0/0`、
   `organs 7273/0/0`、`injection 8252/0/0`。
   **结论**：玩家能「看」记忆，几乎不能「处置」记忆 —— 除了记忆控制中心那一处。
   这不是缺功能，是**功能建了一屋子、只开了一扇门**。

2. **记忆本体没有条目级编辑面。**
   实测 `grep -c`：`editMemory=0` / `updateMemory=0` / `removeMemory=0` / `forgetMemory=0` /
   `correctMemory=0` / `pinMemory=0` / `memoryList=0`（`index.js` 全部零命中）。

   只有测试 `v316_three_core` / `v3264` 调用）。
   ⇒ 玩家想「这条记错了，改掉」时，产品面无路可走。
   而 `memorycenter` 的 9 个 handler 全部围绕**证据裁决**（`row.revoke` / `row.dispute` /
   `row.repair.preview` / `row.export` / `saved.replay` 等），没有一个是「改记忆正文」。

3. **24 件内核有实现、在册、单元测绿，产品端零入口。**
   `tests/audit/module_consumption_ledger.json`：244 模块中 `prod_call_sites=0` 的 **24 件**，
   `why` 统一写着「存量独立算法库或工作台套件（待后续阶段接线或降级）」—— 这措辞本身是**待办**。

   - 实测 `era-continuation-inheritance-tree.js` 全文 **2138 字符 / 1 个导出函数**
     （`inheritEraArtifact`）；`institutional-collective-memory.js` **2217 字符 / 1 个导出函数**

4. **真宿主验证的门建好了，一次都没真跑过。**

   ⇒ **「仍未跑真实 SillyTavern UI」这句诚实边界，从 v3.427 一路写到 v3.431，四个版本没动过。**

5. **面板三态纪律只治了 15 处，其余仍是「空 = 没数据」。**
   `scan_ui_panel_drive` 的 W7 现已四档不同形（有数据 10 / 真没有 3 / 缺席 15 / 失败 14）——
   这是 L12-O4 的成果。但它覆盖的是**面板驱动面**，而上面 Problem 1 那 24 个只读视图里，
   缺席与空仍是同一句话：`relations` 用 `faceRead` 兜底写「图谱服务缺席」，
   `vectors` 写「需要配置 Embedding API 后才会产出向量」，
   `volumes` 写「活跃摘要超过阈值后会自动折叠生成」——
   **三者都是「为什么没有」的散文，但机器读不出区别**（无 `data-` 状态属性）。

6. **`PLAN.md` 的版本行与门禁行仍无人看守（v12-O6 只收干了一半）。**
   实测 `PLAN.md:57` 写 **v3.430.0**（实际 3.431.0）、`PLAN.md:58` 写「**429** 测试文件 / 71 个 audit 脚本」
   （磁盘 430 个 test 文件），而 `gen_plan_baseline --check` 仍报「一致」——
   因为该工具只改写/核对**体量行**（第 61 行：11862 行 / 1218 成员 / 244 项，已正确）。
   ⇒ 「读数由机器看守」这句话目前只对三行里的**一行**成立。

结论：本仓的病从「机制建成、产品零消费」（L12 主题）往下走了一层 ——
**产品面建成、玩家只能看不能动**；而唯一能证明「动了之后真没问题」的真宿主门，
建好就没人跑。本期九项全部对准这两条，**不开新内核、不加新机制**。

## Proposal

### L13-O1 · 真宿主门从「建好」到「真跑一次」（一次真跑，不是再建门）

- **真实现场**：Problem 4。`tests/audit/realhost_readings.json` 不存在；
  `_realhost_suite.mjs` 三条最小回归（装载面 / 写盘闭环 / 世界线纪元）一条都没落盘。
- **工作包**：
  - 解决「ST 不在跑」这个前提：写 `tools/realhost_up.mjs` —— 用环境内**已有**的
    Playwright `chromium-1148` 起一个 headless 浏览器 + 本地静态 ST 壳，
    或明确文档化「外部先起 ST，再跑本命令」的两步式，**不许把它写成「跳过」**；
  - 真跑一次 `node tests/audit/_realhost_suite.mjs`，让 `realhost_readings.json` 真实落盘；
  - 三条读数逐条进 `PLAN.md` 的诚实边界段（**把四版没动的那句话按实测改写**，
    例如「v3.43x 已跑真宿主，装载面 X / 写盘闭环 Y / 世界线 Z；仍未覆盖：真机触摸、窄屏观感」）。
- **禁止的解法**：把 `bail` 改成 `skip` 冒充通过；手写一份 `realhost_readings.json`；
  把该门塞进 `npm test`（会拖垮全量并引入浏览器依赖）。
- **验收**：`realhost_readings.json` 在场且 `measured_at` 是当版；三条读数每条都能复算出同一结果；
  起不来时仍 exit 2（**未执行 ≠ 通过**）；`PLAN.md` 诚实边界段不再出现「仍未跑真实 SillyTavern UI」
  这句无版本的话。
- **规模**：**2~3 天**（主要成本在 ST 壳与浏览器拉起，不在判据）。

### L13-O2 · 记忆条目级编辑面（玩家第一次能改一条记忆）

- **真实现场**：Problem 2。`editMemory/updateMemory/removeMemory/forgetMemory/correctMemory/pinMemory`
  在 `index.js` 全零；`memorycenter` 九个 handler 全是证据裁决，无一改正文。
- **工作包**（**只做编辑，不做批量管理** —— 批量是下一期的事，混在一起会做不完）：
  - 内核侧：`memory-center.js` 增 `row.edit` / `row.pin` / `row.forget` 三个动作
    （`kind: 'write'` / `writes: true` / `undo: true`），**沿用既有动作声明表**
    （不改结构，只加行）；正文写入必须走 `memory-organs` 的既有 slot，**不新建第二套事实库**；
  - 宿主侧：`index.js` 增三个转发桩（一行一个，业务落 `memory-center.js`，沿用 L12-O1 纪律）；
  - 面板侧：`settings-ui.js` 的 `_memoryCenterHandlers` 增三个 handler；
    编辑走**行内展开**（不弹新窗，避免与既有 overlay 抢焦点）；
  - **撤销必须真能撤回**：`row.edit` 的 undo 要落到既有 oplog（`data-view="oplog"` 已存在，
    正好把「改了哪条」显示出来 —— 这一格现在是空的，编完就有人读了）。
- **禁止的解法**：直接改 `memory-organs` 的内部数组而不走 slot；编辑只改 UI 缓存不落盘；
  给 `row.edit` 加 handler 但 `undo: false`（那等于给玩家一个不可撤回的删除按钮）。
- **验收**：真机点得开一条记忆 → 改正文 → 刷新仍在 → oplog 里有一条 → 撤销后逐字还原基线；
  三条真源码破坏负控制（改 slot 绕过 / undo 不落盘 / oplog 不记）；
  `scan_ui_panel_drive` 的 W7 对新增三态各有一档。
- **规模**：**3 天**（含 oplog 接线与撤销回环）。

### L13-O3 · 只读视图的机器可读三态（把「为什么没有」变成属性）

- **真实现场**：Problem 5。`relations` / `vectors` / `volumes` 等 20+ 视图的空态是散文
  （「图谱服务缺席」「需要配置 Embedding API」「超过阈值会自动折叠」），
  **语义完全不同却同形**：一个是「模块没装」，一个是「装了但没配置」，一个是「配了但还没到阈值」。
- **工作包**：
  - 统一三个写进 `CONTEXT.md` 的态名：`absent`（模块没装上）/ `empty`（装上了、真没有）/
    `blocked`（装上了、有数据源，但缺前置条件，如未配 API Key）；
  - 每个只读视图根节点加 `data-face-state="absent|empty|blocked|ok"` +
    `data-face-why="<reason-code>"`（reason code 用短横线英文，不写中文散文）；
  - `faceRead` 兜底路径**必须给出 reason code**，不许只回空数组；
  - 判据：`scan_ui_panel_drive` 扩一档「每个 `data-view` 分支的根节点必须带 `data-face-state`」，
    漏一个即红。
- **禁止的解法**：把三态都写成 `empty` 蒙混；只加属性不给 reason code；
  在面板里自己算「该不该有数据」（三态判定必须来自内核返回值，不是面板猜）。
- **验收**：同一视图三种造法（摘模块 / 清数据 / 撤 Key）**产出三个不同 `data-face-state`**；
  散文文案随态变化（absent 时说「没装」，blocked 时说「缺什么」）；
  破坏 `faceRead` 的 reason code ⇒ 判据红。
- **规模**：**2 天**。

### L13-O4 · 面板视图的入口可达性（24 个只读视图当前怎么进的？）

- **真实现场**：Problem 1。25 个 `data-view`，但入口卡只有少量 `ls-clickable` 卡片
  （实测 `settings-ui.js:244` 一张 `data-view="memorycenter"` 卡）。
  其余 24 个视图**是否都能从界面点进去，没有任何读数**——
  `scan_ui_binding` 判的是「声明键 ↔ 渲染控件」，不判「视图有没有入口」。
- **工作包**：
  - 先出**实测清单**：逐个 `data-view` 反查它的 `showBrowser('<view>')` 调用点，
    分三类：`导航可达`（有卡片/按钮点进去）/ `仅代码可达`（只能被别的流程跳进来）/
    `零可达`（只有定义，没有任何调用）；
  - `零可达` 的一律**二选一**：接一个入口，或删掉（**不许留着**，那正是本仓反复治的形态）；
  - `仅代码可达` 的写明「从哪条流程进」，并在该流程末端加一行「查看完整列表 →」的跳转；
  - 判据：`scan_ui_view_reach.mjs`，输出三类计数，`零可达 > 0` 即红。
- **禁止的解法**：把所有视图塞进一个大列表页凑「可达」（那不是可达，是又一个陈列）；
  给零可达视图加 `void this.showBrowser(x)` 假调用。
- **验收**：三类计数真实打出来；`零可达 = 0`；每个「导航可达」的入口在真面板里点得开
  （至少 5 个真点过并记录）；删掉的视图在 `ITERATION_LOG` 写明「被哪一版取代」。
- **规模**：**2 天**（清点半天 + 接线一天 + 真点半天）。

### L13-O5 · 世界线/纪元口径对玩家的可读化（已有编辑器，缺「看懂」）

- **真实现场**：v3.429.0 已交付结构化编辑器 + 实时读数（`data-wl-readout` 六属性），
  但它假设读者知道「纪元 = 层标记@楼层」。卡作者读 `docs/worldline-authoring.md` 能懂，
  **普通玩家打开面板看到的是一串 `alpha线@47`**，不知道那意味着什么、也不知道「前史缺口」
  会怎么影响自己看到的记忆。
- **工作包**：
  - 面板读数行旁加一段**随态变化的解释**（三态各一句人话，不做统一模板）：
    `none` ⇒「你还没登记过世界线跳转，所以『跨世界线记忆不串味』这条保护**现在没生效**」；
    `gap` ⇒「首跳之前那段楼的记忆分不清属于哪条世界线，那批记忆会被判成『判不了』（不会当成事实）」；
    `ok` ⇒「首跳在第 1 楼，前史已覆盖」；
  - 关键：**「没生效」不能说成「安全」** —— 这是 v3.429.0 已在代码注释里定的纪律，
    但读数是给机器看的（`data-wl-readout`），人看不到；
  - 加一枚「我受影响的是哪几条」：点了列出当前 `detail='undecided'` 的记忆条目（只读，不写）。
- **禁止的解法**：把解释写成一段静态帮助文本（那就不是「随态」了）；
  用 `alert` 或新窗口（沿用行内提示）。
- **验收**：三态各截图级验证文案不同；`none` 态文案里**不出现「安全」二字**；
  「受影响条目」的条数与内核 `recallPreview` 的 `undecided` 计数逐字相同；
  破坏 `why` 分支 ⇒ 文案退回通用文本且判据红。
- **规模**：**1.5 天**。

### L13-O6 · 注入面的「这一轮用了什么」可复算（当前只有总量）

- **真实现场**：`data-view="injection"` 分支 8252 字符 / **0 按钮 / 0 数据属性**，
  是纯陈列；而本仓的核心承诺是「可回源、可撤销」——
  **玩家看不到「这一轮模型到底吃进了哪几条记忆」**，只能看到一个总量或分类统计。
  这与 `docs/planning` 里多份计划说的「注入预演」不是一件事：预演是**生成前**，
  玩家要的是**生成后**的「实际吃了什么」。
- **工作包**：
  - 生成回执里取**逐条**记录：条目 id / 来源面（哪类记忆）/ 占多少字符 / 是否被裁掉（含裁剪理由码）；
  - 面板 `injection` 视图改成**列表 + 逐条可展开**，每条给「凭什么进来」（命中原因码）；
  - 加一枚「这一轮有没有条目因为预算被裁」的显式读数（**裁了要看得见**，
    这是本仓最容易静默损失的一格）；
  - 判据：造一轮「预算刚好不够」的注入，被裁条目必须**同时**出现在面板与被裁计数里。
- **禁止的解法**：只显示总数；把「被裁」当成「没命中」（两者不同形）；
  面板自己按预算重算一遍（**必须读回执**，重算就是第二套真源）。
- **验收**：真跑一轮生成 → 面板列出逐条 → 与回执逐字一致 → 人为压低预算后「被裁」非 0 且有名有姓；
  负控制：回执少一条 ⇒ 面板与它同源（不会多出来），但判据报「回执与注入不一致」。
- **规模**：**2.5 天**（回执结构要真读一遍，不能照猜）。

### L13-O7 · `PLAN.md` 版本行与门禁行交接给机器（v12-O6 补刀）

- **真实现场**：Problem 6。第 57 行版本行写 v3.430.0、第 58 行门禁行写 429，
  而 `gen_plan_baseline --check` 报「一致」—— 它只守体量行。
- **工作包**：
  - `tools/gen_plan_baseline.mjs` 的射程从「体量行」扩到「版本行 + 门禁行 + 体量行」三行，
    `--check` 三行全核；`--write` 三行全写；
  - **不许**把版本号写死进工具（必须从 `index.js` 的 `VERSION` 读）；
  - 门禁行的「测试文件数」必须**数磁盘**（`tests/*.test.mjs`），不是数上一版登记值。
- **禁止的解法**：手工把 429 改成 430 就算完（下一版照样漂）；
  新增一个只看版本号的小门（那是第二个真源）。
- **验收**：手改三行任一数字 ⇒ `--check` 红；`--write` 后三行全对；
  把 `VERSION` 改成 `9.9.9` ⇒ 版本行跟着变（证明是读来的不是写死的）。
- **规模**：**0.5 天**。

### L13-O8 · 记忆删除的「痕迹可查」（当前删除即消失）

- **真实现场**：`memory-organs.js:1012` 的 `deleteMemory` 是
  `c.core = c.core.filter(...)` / `c.recent = c.recent.filter(...)` ——
  **直接从数组里摘掉，不留任何痕迹**。这与本仓主轴「可回源、可撤销、可接续」直接冲突：
  玩家删掉一条记忆后，**没有任何地方能回答「我删过什么」**。
  （`oplog` 视图存在，但删除动作不走它。）
- **工作包**：
  - 删除改为**软删**：条目移入 `tombstones`（带 `deletedAt` / `deletedBy` / `reason`），
    `of()` 默认不返回 tombstone（**默认行为逐字不变**，避免影响既有 430 个套件）；
  - `oplog` 视图增「已删除」分区，可**恢复**（恢复 = 从 tombstone 移回原槽）；
  - 保留期：不自动清理（数据量极小），但提供「手动彻底清除」并二次确认；
  - 判据：删 → 记忆列表少一条且 oplog 多一条 → 恢复 → 逐字还原（含 `id`）。
- **禁止的解法**：把删除做成「标记位 + 过滤」但 `of()` 忘过滤（那会让删掉的记忆继续被召回）；
  恢复时重新生成 `id`（**id 必须原样回来**，否则引用它的地方全断）。
- **验收**：删除/恢复双向逐字比对；`of()` 在软删后不返回该条（默认行为不变的证据）；
  召回面按 `of()` 取数 ⇒ 删掉的不会被注入；负控制：把 tombstone 过滤拿掉 ⇒ 判据红。
- **规模**：**2 天**。

### L13-O9 · 「设置改了但没生效」的当场自证

- **真实现场**：`scan_ui_interaction` 的 V5（保存落地 4 次）/ V6（重开保留）已在，
  但它验的是**通用收集器**；而本仓有多处设置是「保存了、要等下一轮生成才生效」
  （注入预算、世界线跳转、静音话题等）。玩家改完点保存，界面无任何反馈说明
  **「现在生效还是下轮生效」**。
- **工作包**：
  - 每个配置项在 `PLAN`/`CONTEXT` 登记一档 `effect_at`：`immediate` / `next-turn` / `next-session`；
  - 面板保存后按 `effect_at` 给**三种不同**的提示（不是统一「已保存」）：
    `immediate` ⇒「已生效」；`next-turn` ⇒「下一轮生成生效」；`next-session` ⇒「重开对话后生效」；
  - 判据：配置项清单与代码里的收集器键双向核对，**没登记 `effect_at` 的键即红**
    （防新增配置时漏登记）。
- **禁止的解法**：全标成 `immediate`（那是最省事也最常骗人的写法）；
  在面板里硬编码一张 `effect_at` 表（必须与登记面同源）。
- **验收**：抽 3 个不同档位的配置项，改完保存看提示不同；把某键的 `effect_at` 删掉 ⇒ 红；
  真机验证 `next-turn` 那一档：保存后当前轮不变、下一轮变（这条要真跑一次生成）。
- **规模**：**1.5 天**。

## Delivery sequence

1. **先让「真」有据（O1 + O7）** —— O1 把四版没跑的真宿主门真跑一次，O7 把 PLAN 的
   三行读数交给机器。这两件是**证据地基**：后面八项都要在 CHANGELOG 里写「真机验过」，
   没有 O1 就只能写「结构证明」。
2. **再开玩家的手（O2 -> O8 -> O3）** —— 先能改（O2），再能撤（O8，删除痕迹），
   再让「没有」说得清楚（O3）。O8 依赖 O2 的 oplog 接线，故排在其后。
3. **再补两个「看不见」的面（O6 -> O5）** —— 注入实际吃了什么（O6）与世界线口径人话（O5）。
   两件都依赖前面建立的「三态 / 回执」口径。
4. **最后收口可达性与生效自证（O4 / O9）** —— 前者是清点（可能删东西，放最后避免边做边改），
   后者是横切面（要等配置清单稳定）。

## Alternatives considered

- **继续做消费清账（L12 那条线的延长）**：否决。`scan_module_consumption` 已报零未登记孤儿，
  24 件留存全部带理由登记；再清一轮只是把 `why` 文案改一改，**玩家感知为零**。
  且 PLAN 顶部明令「守卫、审计、台账不独立占名额」。
- **把 24 件零消费内核一次性接线**：否决。实测其中 9 件是**骨架内核**
  （`era-continuation-inheritance-tree` 2138 字符 1 个函数），接线 = 先写内核再写产品，
  是两件事捆一起，必然做不完。本期一件不碰，留给专门一期。
- **把面板 24 个只读视图全部做成可编辑**：否决。那是 24 条独立业务，不是一期能收口的量；
  本期只做**记忆本体**（O2/O8）这一条最痛的主线，其余用 O3（三态）+ O4（可达性）
  先把「现状说清楚」，下一期再按真需求排。
- **用 `--update` 抬各类基线**：否决，沿用 L12 纪律。
- **跳过悬挂类工作**（「反正跑不了」）：否决。O1 的任务不是「建门」，
  而是**证明这件事在当前环境里做不到 or 做到**，并把结论写进诚实边界 —— 四版不动的
  那句话本身就是一种假绿。

## Acceptance criteria

九项都必须：

- 给出**可复算命令与读数**（写进该项正文或证据页）；
- 带至少一条**真源码破坏负控制**（破坏源文件 -> 行为真变 -> 还原校验；不是对副本断言、
  不是写死模拟常量）；
- 产品端改动要有**真面板可点的入口**（O2 / O5 / O6 / O8 尤其），不能只出 API；
- 诚实边界如实写：哪些只有结构证明、哪些真机验过（**O1 之后这条才有资格区分**）。

## Risks

- **O1 是本期最大风险，且可能失败**：环境里没有在跑的 SillyTavern。
  两条出路：自建静态壳（成本高但可控）或两步式文档（成本低但要人能执行）。
  **失败也要如实落盘**：写成 `verdict: 'environment-unavailable'` 并保留 exit 2，
  **不许改判据降级成 skip**。
- **O2 / O8 都动 `memory-organs` 的存取路径**：430 个套件里有多份断言 `of()` 的返回形状。
  纪律：默认行为逐字不变（软删对 `of()` 透明），新行为一律**显式开关或新读口**。
  动之前先跑 `tests/v316_three_core.test.mjs` 与 `v3264_a1_memory_organs.test.mjs` 两份做基线。
- **O4 可能删掉视图**：删之前必须确认「零可达」是**实测**而不是 grep 没找到
  （`showBrowser` 可能被动态拼字符串调用 —— 这正是 L12 教训里「grep 模块名 = 0 是假信号」
  的同族坑）。清点必须按**绑定**判，不按字面量判。
- **O6 依赖回执结构**：如果回执里现在没有逐条记录，本条会变成「先改回执再改面板」，
  成本上浮。**先读回执实体再定规模**，不许照计划原文估。
- **O9 的 `effect_at` 清单是一次性人工登记**：有漏登记风险，所以判据要**双向**
  （配置键 <-> 登记面），只判单向必漏。
