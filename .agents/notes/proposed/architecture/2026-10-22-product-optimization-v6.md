# Agent Note: 第六期记忆优化——从记住条目到理解持续经历

Status: proposed

## Problem

基线为 v3.353.0 / `a6025ba`，取证日期 2026-10-22。本轮只规划，不实施、不升版。第五期已有实现，不能把旧提案中的缺口直接当成当前事实。

现役召回、关系史、视角卡、时态事实、材料包、目标树与研究集合已构成丰富底座；下一轮价值不在再加检查器，而在让这些材料形成连续的理解与创作支持。[现状证据](../../../../docs/planning/2026-10-22-product-evidence-v6.md)区分代码观察、合成模块实跑与未来验收；下列需求是基于能力边界提出的产品判断，不伪称已经做过用户访谈或真实宿主复现。

## Proposal

九项均为完整产品能力跃迁。这里的开创性指本项目新增的机制组合与体验，不宣称未经竞品验证的全球首创。每项必须同时交付生产链路、持久化/重开、原生可用入口及生成消费，不能以一个纯函数或按钮结项。与[拓展九项](../feature/2026-10-22-product-expansion-v6.md)共用既有数据所有者，不另建第二记忆系统。

### M6-O1 · 连续经历重建：把散落往事召回成一件完整的事（P0 / XL）

- **现状与需求**：[M-E1/M-E4](../../../../docs/planning/2026-10-22-product-evidence-v6.md#memory-evidence)。多源召回、事件四段与因果导航已存在；新目标不是再画图，而是用户说“上次筹展那件事”时，获得跨场景的起因、行动、转折、结果及尚未结束的部分。
- **机制与完整体验**：以已有事件/事实引用构成可修订的经历单元；结合人物、时间、地点、约定变化提出合并候选，保留用户拆分权。检索先定位经历，再按问题展开证据与未完后续；结果可直接交给续写材料。
- **增量边界**：不复制 causal-chain 的边，不把时间接近直接当因果，不重做第五期长节点尾部索引。新增的是跨楼经历归属、演变与可展开的召回结果。
- **落点与依赖**：`event-completeness.js`、`causal-chain.js`、`unified-recall.js` → `index.js::recallMemory/buildInjection` → `memory-center.js`；不依赖本期拓展项。
- **验收下限**：① 60楼、三次同名活动与一段闪回中，正确重建指定活动且逐段有出处；② 用户拆开误并经历，重开后问答与续写均跟随；③ 删除结果来源后，保留起因而不再断言事情已完成。大更新必须完成“查一事—展开—校订—带入下一幕”全程。
- **代价/不做**：聚类错误比漏聚危险；自动结果先作为可解释候选。不承诺单靠关键词理解全部经历。

### M6-O2 · 记忆问题求解器：从找相关段落到跨证据回答复杂问题（P0 / XL）

- **现状与需求**：[M-E1/M-E5](../../../../docs/planning/2026-10-22-product-evidence-v6.md#memory-evidence)。已有自然语言问答、条件继承和时点查询；“为什么先答应又退出，与谁掌握的信息有关”需要多步比较，不能只把几条命中拼成回答。
- **机制与完整体验**：将问题分解为人物/时间范围、待比较命题、证据连接与回答结构；分别执行既有检索，再把支持、反证、缺失环节放进可展开答案。后续追问修改求解目标而非清空全部工作。
- **增量边界**：不是重做 M4-X4 多轮问答或 M5-O1 时点传参；新增有界的多跳求解与反证并列，不输出模型私有思维链，只展示可核查依据和结论。
- **落点与依赖**：`qa-thread.js`、`evidence-query.js`、`testimony-board.js`、`relation-history.js`及宿主问答入口；M6-O1可增强召回，不作启动前置。
- **验收下限**：① 同一问题需连接至少三处独立原文才可答，答案覆盖连接关系；② 加入一条相反证词后解释随之改变，不按重复转载数投票；③ 缺关键环节时只给条件结论，修改时点后全部依据按新范围重求。至少完成20个长线任务的现版对照，预先固定评分表。
- **代价/不做**：有界检索深度与明确调用预算；不将语言模型给出的“因果”自动登记成事实。

### M6-O3 · 可展开的多分辨率记忆：压缩不再只剩结论（P1 / XL）

- **现状与需求**：[M-E1/M-E6](../../../../docs/planning/2026-10-22-product-evidence-v6.md#memory-evidence)。已有短长期巩固、金字塔摘要、保底句与分段检索；读者仍需要在“快速回顾”和“重看关键原话”之间自由切换，而非永远增加注入长度。
- **机制与完整体验**：同一经历保留概览、转折骨架、可定位原话三个分辨率，以引用而非重复正文连接；按当次问题和预算选择展开层。已压缩内容仍可从原档按需唤回，缺源明确显示不可展开。
- **增量边界**：不是提高长度上限、换遗忘分数或再补压缩守卫；新增可逆展开协议与按问题选粒度的实际消费。
- **落点与依赖**：`stm-ltm.js`、`node-rollup.js`、`memory-core.js`、`unified-recall.js`、注入预算链；优先接 M6-O1 的经历引用，兼容旧节点。
- **验收下限**：① 500楼故事压缩后可在原生页从卷概览下钻到关键原话；② 固定注入预算比较现版与新版，至少保住承诺、例外、转折三类要点且不增加矛盾；③ 缺源与仅未展开不同，重开/分卷后引用仍正确。公开比较材料与结果，不先许诺提升百分比。
- **代价/不做**：多级摘要可能互相偏离，派生层随来源修订；不另存整套原文数据库。

### M6-O4 · 人物自传式记忆：让角色带着自身经历进入下一幕（P1 / XL）

- **现状与需求**：[M-E2/M-E4](../../../../docs/planning/2026-10-22-product-evidence-v6.md#memory-evidence)。CharacterMemoryBank已有核心/近期文本，另有关系史、视角卡和启发式弧光。需求是把“此人经历如何塑造现在的态度”用于稳定长线人物，而非只返回几条文本。
- **机制与完整体验**：组织人生阶段、重要选择、关系转折、自我陈述与未解决经历；同一人物按场景选择有关阶段，以“过去怎样—后来发生什么—现在仍保留什么”供生成。作者可编辑阶段边界，不把人格锁成分数。
- **增量边界**：不是首次做角色档案/弧光，也不覆盖人物卡。过去发生什么由本项管理；“他如何解释并相信它”属于 M6-X1，二者分开。
- **落点与依赖**：`memory-organs.js::CharacterMemoryBank`、`perspective-card.js`、`relation-history.js`、`narrative-pulse.js` → 角色查询与注入；依赖 M6-O1，M6-O3提供按需展开。
- **验收下限**：① 三阶段人物在回忆和当下两场景使用不同经历材料；② 同名人物与伪装身份不被合成一个人生；③ 一次关键选择改变后续自传摘要，但未发生的新性格不得自动写成正史。完成跨百楼的原生查询与至少两种模型的内容对照。
- **代价/不做**：反对固定“启程→归真”套所有人；阶段和态度是可修改解释，不是心理诊断。

### M6-O5 · 双时间经历：分清何时发生、何时被得知（P0 / XL）

- **现状与需求**：[M-E3](../../../../docs/planning/2026-10-22-product-evidence-v6.md#memory-evidence)。事实账已有楼层有效区间、剧情钟和知识轨迹。新需求是同一件迟到披露的旧事能同时回答“那天发生了什么”和“当时这个人知道什么”。
- **机制与完整体验**：给事件有效时间、文本披露时间、角色获知时间建立可连接但不互相代替的坐标；支持部分日期、相对先后、闪回与不确定区间。查询、年鉴和场景材料使用同一时间投影。
- **增量边界**：不是 M5-O1 的时点参数修复；不是以新字段名宣称整个仓库没有时间功能。升级的是事实、剧情钟、知识轨迹之间的联合时序语义。
- **落点与依赖**：`fact-version.js`、`story-clock-parse.js`、`knowledge-trace.js`、`perspective-card.js`与提取/查询链；先兼容旧档“未知坐标”，不猜日期。
- **验收下限**：① 第100楼揭露第10楼以前发生的搬迁，当前问答可知而第20楼人物视角不可知；② 同一人物分别获知两个冲突版本，历史视角仍保留当时版本；③ 日期不全、跨日和闪回混用时返回区间或未知，不用楼层顺序伪装剧情日期。
- **代价/不做**：迁移影响广；沿现有事实与知识所有者扩展，不引入另一套时间数据库。

### M6-O6 · 场景上下文编排：让记忆服务当前互动，而非塞一包资料（P0 / XL）

- **现状与需求**：[M-E1/M-E7](../../../../docs/planning/2026-10-22-product-evidence-v6.md#memory-evidence)。现有材料包有 meet/reunion/advance/resolve 四种任务，场所和约定已接线；长场景中互动任务会变化，静态选材不足以持续支撑行动。
- **机制与完整体验**：把本幕的参与者、各自可知、行动目标、硬约束、可调用旧事和未解决问题编排为场景状态；随着玩家选择，从准备、交涉到转折按需改编材料，保留不同人物的私有视角。
- **增量边界**：不是给四种任务再添几个枚举，也不替模型写整场故事。新增场景过程中可更新的记忆供给与原生“本幕材料”操作面。
- **落点与依赖**：`material-pack.js`、`index.js::_materialInventory/buildInjection`、`perspective-card.js`、`commitment-ledger.js`；依赖 M6-O1/O5，兼容现有预算与手机桥。
- **验收下限**：① 同一场五轮互动出现新消息后，下一轮材料相应变化且旧约束不凭空消失；② 两名角色得到不同知情材料，叙述者材料不自动共享给角色；③ 取消本幕或切换会话后不残留任务。用同预算对照观察约定遗漏与错误引用，而非只测字符串包含。
- **代价/不做**：不建多智能体后台自治，不用隐藏提示覆盖用户写作意图。

### M6-O7 · 关系动力记忆：从转折列表到理解关系为何保持或改变（P1 / XL）

- **现状与需求**：[M-E4](../../../../docs/planning/2026-10-22-product-evidence-v6.md#memory-evidence)。有向关系史和共同知情已经存在；下一步是让帮助、失约、修复、回避等经历在长期互动中形成不同结果，而非全部折算“好感增减”。
- **机制与完整体验**：以既有事件作依据，整理双方期待、付出、未回应事项、修复尝试与关系转折条件；为重逢/冲突场景提供“仍在意什么、哪些已释然、哪一方尚不知道”的材料。
- **增量边界**：不是重画关系图，也不自动判定谁欠谁。共同往事仍由既有模块查，本项新增可更新的关系互动模型。
- **落点与依赖**：`relation-history.js`、`relation-mutual.js`、`commitment-ledger.js`、`perspective-card.js`；依赖 M6-O1/O5，进入 M6-O6 的关系材料分区。
- **验收下限**：① A道歉而B尚未收到时不能显示双方已和解；② 反复帮助与一次失约并存时保留多种依据，不以单值覆盖；③ 旧约定已释然之后不持续施压提醒，但历史转折仍可查。原生编辑、重新生成和重开均验证。
- **代价/不做**：不把关系建模用于现实操控建议；只支持虚构人物叙事，拒绝道德评分器。

### M6-O8 · 持续研究记忆：资料改变时，结论能继续生长（P1 / XL）

- **现状与需求**：[M-E8](../../../../docs/planning/2026-10-22-product-evidence-v6.md#memory-evidence)。资料导入、段落改版、跨书专题与可追溯结论已存在。真实新增需求是持续维护一个研究问题，而不是每次改书后重写整份报告。
- **机制与完整体验**：将专题组织成问题—主张—证据/反证—未决条件；资料更新只重算受影响的主张，并保留作者的论述修改。读者看到新证据如何改变结论，可采纳、保留异议或继续研究。
- **增量边界**：不是重新实现摘录回源、版本差异或失效扫描；新的产品成果是长期专题的论点演进与局部续作。
- **落点与依赖**：`research-collection.js`、`lore-crosscheck.js`、`lore-import.js`、`qa-thread.js`与原生研究入口；复用已有依赖引用，M6-O2增强查证。
- **验收下限**：① 三本资料支撑五个主张，修改其中一段仅重算受影响主张；② 相互矛盾版本可并存，未确认不替作者裁定；③ 重开后可从研究问题继续，正文已编辑段不被静默覆盖。至少一次真实资料导入→改版→研究续作宿主旅程。
- **代价/不做**：生成结论属于草稿；不把研究资料自动当成剧情正史，不引入外部数据库。

### M6-O9 · 长期意图推进：让目标会遇阻、改道与付出代价（P1 / XL）

- **现状与需求**：[M-E9](../../../../docs/planning/2026-10-22-product-evidence-v6.md#memory-evidence)。现有目标前置条件按事实状态派生可推进性；但实现大目标往往有互斥路径、资源约束和阶段性放弃，不是勾完清单。
- **机制与完整体验**：为目标保存可替代行动路径、角色承诺、资源/时间约束和可接受代价；从新事件识别进展或障碍，提出重新规划候选，作者确认后才改变路线。
- **增量边界**：不重做 M5-X2 目标树，不扩大条件数量充数；新增“同一目标如何改道”的持续意图模型。未来后果的条件投影归 M6-X3，本项只管理当前目标选择。
- **落点与依赖**：`goal-tracker.js`、`commitment-ledger.js`、`fact-version.js`、`material-pack.js`；依赖 M6-O1/O5。
- **验收下限**：① 两条互斥筹展路线，选定其一后另一条不显示已完成；② 资源耗尽或关键角色退出，给出改期/缩小范围等有据选项而不是自动成功；③ 放弃后重启目标保留旧尝试与已付代价，重开后可继续。至少一条跨十个剧情事件的完整推进演示。
- **代价/不做**：不建全能任务自动执行器，不替玩家选择最优剧情。

## Delivery sequence

建议与另一仓按证据页的六个产品批次推进，而非“一项一版”反复补丁。本仓优化顺序为 O1/O5 → O2/O3/O6 → O4/O7/O9 → O8。可并行工作不构成硬依赖；原生记忆界面必须独立可用，不能只有手机装上后才算交付。

## Alternatives considered

- **只修已发现的传参、长度与按钮问题**：风险低、见效快，但不足以满足本轮大更新标准；这些作为相关功能的必要配套，不占九项。
- **再建统一超级账本**：数据看似集中，但会复制事实、知识和关系所有者，迁移风险远超收益；采用引用式经历层与现有所有者的查询组合。
- **全部交给更长提示词与更大模型**：原型快，但缺乏持久化语义和可编辑依据；模型只负责受限解释/草稿，不取代数据机制。

## Acceptance criteria

本文件恰含 M6-O1～O9 九项；每项必须交付完整用户旅程，不用单测、自检、导出API代替功能。实施前固定现版对照故事与评分任务，实施后分别报告：纯模块、真实宿主点击、生成内容效果。模型质量未达门槛的条目只能标试验，不能宣称完成。

## Risks

主要风险是过度推断、上下文成本和新旧语义迁移。所有派生解释与原事实分离；沿现有存档与预算机制，资料不足可未知。产品功能占主要实施资源，测试/迁移随功能收口，不新增常驻审计平台。全量回归按仓库纪律在整批收口执行，禁止用不断修守卫替代上述体验交付。
