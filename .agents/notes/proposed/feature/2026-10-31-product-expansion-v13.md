# Agent Note: LonSha 第十三期拓展与独有机制计划

Status: proposed

> **期号口径**：本份为第十三期拓展面，编号 `L13-X1 ~ L13-X9`。期号依据与撞号防范见
> [优化计划](../architecture/2026-10-31-product-optimization-v13.md) 开篇。
>
> **与优化面的分工**：优化面（O1~O9）治「已经建好而玩家碰不到」；本面九项全部是
> **本仓确实没有的新面**。两条硬纪律：
> - **不新增第二套事实库**：任何新面只能读/写既有槽位（`worldProg` / 证据账 / oplog），
>   需要新数据必须先接既有 owner，接不上就降级成只读。
> - **不开新内核**：本面九项合计只新增两件内核（X1 的「可审阅回放器」与 X8 的
>   「跨卡导出编排」），其余全部是既有内核的新组合。
>
> **取证纪律**：每条「真实现场」均在 2026-10-31 实读，读数写在
> [第十三期证据页](../../../docs/planning/2026-10-31-product-evidence-v13.md)。
>
> **为什么这九项而不是别的**：第九期拓展的九件内核（`L9-X1~X9`）已有 **9 件挂规划标签但
> 产品零入口**，实测其中多数是**骨架**（`era-continuation-inheritance-tree` 全文 2138 字符
> 只有 1 个导出函数 `inheritEraArtifact`）。所以本面**不把它们当待接线资产**，
> 而是把它们该解决的问题**重新按产品需求写一遍** —— 内核不够就补，够就直接用。

## Problem

本仓的机制已经很密（`extra_js` 244 项、面板 25 视图、诊断行成体系），但**玩家能主动
发起的事情很少**：绝大多数能力是「模型生成时顺手用上」，而不是「我想让它做这件事」。
逐条实测：

1. **没有任何「回放」面能回答「这段记忆是怎么变成现在这样的」。**
   `data-view` 里有 `timeline` / `deltas` / `conflicts` / `archive`，都是**当前状态**的陈列；
   `oplog`（1179 字符 / 0 按钮 / 0 属性）是操作流水，不是**某条记忆的沿革**。
   玩家问「为什么角色记得这件事却忘了那件事」时，产品面无法回答。

2. **反事实/推演内核存在，但产品零入口。**
   `counterfactual-experiment-bench.js`（L9-X4）在 244 模块台账里 `prod_call_sites=0`，
   `index.js` / `engine-*.js` / `settings-ui.js` 均零命中。而「如果当时没有跳世界线」
   这类问题是本仓核心玩法的一类，完全无处可问。

3. **多视角材料投影同样零入口。**
   `multi-perspective-theater-bench.js`（L9-X7）`prod_call_sites=0`；
   而面板有 `povs` 视图（675 字符 / 0 按钮 / 2 属性）—— **只列视角名，不投影内容**。

4. **记忆考古内核零入口。**
   `memory-archaeology-gap-bench.js`（L9-X3）`prod_call_sites=0`，只在自身文件内被引用。
   而「证据缺口」是本仓证据裁决体系里最需要人参与的地方（哪里缺证据，人最清楚）。

5. **没有「跨卡/跨对话的记忆迁移」产品面。**
   实测 `importMemory=0`（`index.js` 零命中）；`memory-organs.js` 有四个 `import(data)`
   但都属内部状态导入；`exportMemoryReport`（`index.js:7560`）产出的是**报告**，不是**可移植包**。
   ⇒ 玩家换一张卡想带上部分记忆，无路可走。

6. **记忆的「季节/沉默」已有内核，但玩家看不到自己把什么静音了。**
   `memory-season-silence-manager.js` 在 `index.js` / `engine-diagnostic-lines.js` 有消费
   （L12-X9 的 `silenceExplainState`），但那是**问「为什么召不回」时才用**；
   没有一个「当前静音清单」的常驻面。

7. **角色习惯/成长证据内核零入口。**
   `character-habit-growth-evidence.js` `prod_call_sites=0`。
   而「这个角色最近养成了什么习惯」是本仓长线人物体验里最容易被玩家察觉的一类。

8. **没有「本轮生成的可撤销快照」面。**
   本仓承诺「可撤销」，`row.revoke` 撤的是**证据裁决**；生成本身写进去的记忆
   （`extract` 后新增的条目）**没有一键回滚到上一轮**的入口。

9. **时代接续内核只有 1 个函数，产品零入口。**
   `era-continuation-inheritance-tree.js`（L9-X9）2138 字符 / `inheritEraArtifact` 一个导出；
   而同主题的 `era-inheritance.js`（6426 B）已由 L12-O1 接管，两者**是不同文件**，
   前者解决的是「跨代传承物四态 + 秘密断代」，产品面完全空白。

结论：本面九项的共同形状是 —— **内核有（或只有骨架）、玩家没有入口**。
与优化面（护栏/可达性）互补，不重叠。

## Proposal

### L13-X1 · 记忆沿革回放（一条记忆是怎么变成现在这样的）

- **真实现场**：Problem 1。`oplog` 是操作流水（1179 字符 / 0 交互），不是条目沿革；
  `deltas` / `conflicts` 是当前状态视图。
- **工作包**：
  - 新内核 `memory-lineage-replay.js`（**本面仅两件新内核之一**）：输入条目 `id`，
    输出沿革链（创建 -> 每次修改 -> 每次裁决 -> 当前态），每节带 `at` / `by` / `why` / `diff`；
  - 数据源**全部来自既有槽位**（oplog + 证据账 + 条目本体），**不新开存储**；
    取不到的节一律标 `unavailable` 并写明缺哪一层（**不编**）；
  - 入口：`memorycenter` 的每行加一枚「沿革」；`timeline` 视图顶部加「挑一条记忆看沿革」。
- **验收**：造一条「创建 -> 改两次 -> 撤一次」的记忆，沿革恰好 4 节且顺序正确；
  某层数据被人为抹掉时该节为 `unavailable` 而不是消失；负控制：把 `diff` 算成空 -> 红。
- **规模**：**2.5 天**。

### L13-X2 · 反事实推演面（把 `counterfactual-experiment-bench` 接到产品）

- **真实现场**：Problem 2。该内核 `prod_call_sites=0`，产品零入口。
- **工作包**：
  - 先**实测内核能力**（读源码，不照名字猜）：它是否支持「给定已发生事件 + 一个改动 ->
    返回受影响的事实/关系/记忆集合」；不支持就先补到能用为止（补的部分计入本条）；
  - 面板新视图 `whatif`：选一个事实做「如果它没发生」，看受影响面（**只读推演，不改数据**）；
  - 严守本仓纪律：推演结果**标注 `hypothetical: true`**，绝不写回任何槽位；
    推演里引用的每条记忆必须带真实 `id`（可点开核对）。
- **验收**：选一个已有事实，推演出「受影响 N 条」且每条都能点开；
  推演前后 `worldProg` 与记忆条目**逐字不变**（这是本条最重要的一条）；
  负控制：让推演写回槽位 -> 判据必红。
- **规模**：**3 天**（内核可能需补）。

### L13-X3 · 视角投影面（`povs` 从列名单到投影内容）

- **真实现场**：Problem 3。`povs` 视图 675 字符 / 0 按钮 / 2 属性；
  `multi-perspective-theater-bench`（L9-X7）`prod_call_sites=0`。
- **工作包**：
  - 选一个视角（角色）-> 投影「该角色**此刻**会知道哪些事、不知道哪些、以为什么」；
  - 三档必须不同形：`knows`（有据）/ `suspects`（有线索未定）/ `blind`（该他不知道，
    且**绝不能显示正文** —— 沿用本仓秘密三刀纪律）；
  - 数据源：证据账的 `scope` + `knower` 名单，**不新开知识表**；
- **验收**：三个视角对同一事件投影出三种不同结果；秘密条目的正文在任何视角下都不出现在
  `blind` 档（负控制：把 `blind` 档漏剥正文 -> 判据红，这是本仓反复治过的一类）；
- **规模**：**2 天**。

### L13-X4 · 证据缺口工作台（`memory-archaeology-gap-bench` 接产品）

- **真实现场**：Problem 4。该内核 `prod_call_sites=0`，仅自引。
- **工作包**：
  - 面板 `archive` 视图（2583 字符 / 0 交互）改造：列出「有结论但证据薄」的条目
    （证据数 <= 阈值），按缺口严重度排序；
  - 每条给三档缺口成因：`no-source`（从没证据）/ `source-lost`（证据被删/裁）/ `contradicted`
    （证据互相矛盾）—— 三档不同形，**不许合成一个「缺证据」**；
  - 动作面只有两个：`去补证`（跳到证据录入）与 `降级`（把该条从事实降为推测）。
    **不提供「一键补全」** —— 那正是本仓明令禁止的「由模型无凭捏造补全」。
- **验收**：三档成因各造一例且面板分列；`降级` 后条目出现在 `deltas` 视图（既有）；
  负控制：把 `contradicted` 合进 `no-source` -> 判据红。
- **规模**：**2 天**。

### L13-X5 · 记忆迁移包（可移植、可审阅、可拒绝的半份记忆）

- **真实现场**：Problem 5。`importMemory` 在 `index.js` 零命中；
  `exportMemoryReport`（`index.js:7560`）产出报告不是可导入包；
  `memory-organs.js` 的四个 `import(data)` 是内部状态导入。
- **工作包**：
  - `export` 出新内核 `memory-migrate-pack.js`（**不新开存储**，只做序列化与校验）：
    选条/按时段/按角色导出 -> 一个**带校验头**的 JSON 包（schema 版本 + 条目数 + 逐条 sha）；
  - `import` 侧：先**预检**（不写盘）-> 报「将新增 X / 冲突 Y / 无法识别 Z」三档 -> 人确认才写；
  - 冲突处理**必须逐条可选**：保留本地 / 用包里的 / 两条都留（标 `conflict`）——
    **不许默认覆盖**。
- **验收**：导出 -> 清空 -> 导入 -> 逐字还原（含 `id` 与 `floor` 引用）；
  造一条冲突条目，预检必须报出来且默认不写入；篡改包内一条 sha -> 预检必须拒绝整包（fail-closed）。
- **规模**：**3 天**（跨对话存储位置要真查）。

### L13-X6 · 静音清单面（我现在把什么静音了）

- **真实现场**：Problem 6。`silenceExplainState` 是「问为什么召不回」时才用；
  无「当前静音清单」常驻面。
- **工作包**：
  - 新增 `data-view="silence"`：列出所有静音（本轮 `ctx.mutedTopicIds` + 持久
    `seasonState.userActions.mute` 两条真源**分列**，沿用 v3.430.0 已有的两源口径）；
  - 每条给 `since` / `until`（若有）/ `why` / **一键解除**；
  - 解除必须**只解这一条**（不许「全部解除」按钮，那会掩盖误操作）。
- **验收**：制造两条不同源静音，面板分列正确；解除一条后另一条仍在；
  召回面验证被解除条目**真能召回**（这条要真跑一次召回，不能只看面板）；
- **规模**：**1.5 天**。

### L13-X7 · 习惯与成长证据面（`character-habit-growth-evidence` 接产品）

- **真实现场**：Problem 7。该内核 `prod_call_sites=0`。
- **工作包**：
  - 面板 `protagonist` 视图（2035 字符 / 0 按钮 / 4 属性）加「习惯」分区：
    按角色列出「最近形成的习惯」与「何时例外」，每条带证据引用（可点开）；
  - 明确边界：**只显示有证据的**，无证据时显示 `empty`（不是「暂无习惯」的安慰话）；
  - 不新增「经验值/等级」类展示（本仓纪律：不把成长做成数值条）。
- **验收**：造 3 条习惯证据 -> 面板按角色分组；把证据删掉 -> 该条消失而非残留；
  负控制：无证据时显示条目 -> 判据红。
- **规模**：**2 天**。

### L13-X8 · 本轮生成的可撤销快照（跨卡导出之外的另一种「回滚」）

- **真实现场**：Problem 8。`row.revoke` 撤的是证据裁决；生成后新增的条目无一键回滚入口。
- **工作包**：
  - 每轮生成前后各记一次**条目集合摘要**（id 列表 + 计数，不复制正文 —— 遵守「不复制正文绕开 owner」）；
  - 面板 `oplog` 视图加「撤销本轮写入」：只回滚**本轮新增**的条目，
    本轮修改的条目改为「标记待复核」而**不自动回退**（回退修改会吞掉别的动作）；
  - 二次确认，且撤销后 oplog 记一条（可再查）。
- **验收**：真跑一轮生成新增 3 条 -> 撤销 -> 恰好少这 3 条、已有的逐字不动；
  本轮改过的条目变成「待复核」而不是被改回去；负控制：撤销顺手回退修改 -> 判据红。
- **规模**：**2.5 天**（要真跑生成，成本主要在跑）。

### L13-X9 · 跨代传承面（把「传承物四态 + 秘密断代」接到产品）

- **真实现场**：Problem 9。`era-continuation-inheritance-tree.js` 2138 字符 / 1 个函数；
  与已接管的 `era-inheritance.js` 是不同文件，产品面空白。
- **工作包**：
  - 先把内核补到可用（四态 `accepted/rejected/reformed/lost` 已声明，需补：
    每态的可读成因 + 与既有 `eraTransitions` 槽的对接）；
  - 面板 `prequel` 视图（两段共 2025 字符 / 1 按钮）加「传承清单」：
    列出跨代物品/规矩及其四态，**`lost` 档必须与「还没传」区分**（前者是遗失，后者是未发生）；
  - 秘密断代：新一代**绝不自动获知**前代未公开秘密（沿用既有 `scope` 判定，不新写一套）。
- **验收**：四种态各造一例且面板分列（`lost` 与 `pending` 不同形）；
  把前代秘密正文泄漏到新一代视角 -> 判据必红（这条是本条最重要的一条）；
- **规模**：**2 天**。

## Delivery sequence

1. **先做只读面（X1 -> X3 -> X7）** —— 三件都只读不写，风险最低，先建立「沿革/投影/习惯」
   三个新视图与它们的三态纪律；这三件产出的三态判定会被后面几件复用。
2. **再做只读推演（X2 -> X4）** —— 推演与缺口工作台都涉及「不改数据但要能操作」，
   是「只读」与「可写」之间的过渡层，先在这里把「hypothetical 不落盘」的口径钉死。
3. **再做写入面（X6 -> X8 -> X9）** —— 三件都会写盘/改状态，按「改动面从小到大」排：
   解除静音（单条）< 撤销本轮（集合）< 传承断代（跨代）。
4. **最后做迁移（X5）** —— 跨对话导出/导入是本期唯一会碰「另一份存储」的一件，
   风险最高，放最后；前面几件建立的三态与校验头纪律正好在这件里复用。

## Alternatives considered

- **直接把 9 件 L9-X 内核接线了事**：否决。实测它们多是**骨架**（2138 字符 / 1 个函数），
  「接线」等于先做内核，那不是接线，是重做。本面按**产品需求**重写问题，内核不够就补。
- **做「一键补全证据」**：否决。它直接违反本仓明令 —— 不得由模型无凭捏造补全。
  X4 只给「去补证」与「降级」两个动作。
- **做「全部解除静音」「全部删除」类批量按钮**：否决。批量会掩盖误操作，
  与「可撤销、可审阅」主轴相反。
- **把迁移做成「换卡自动继承」**：否决。那会把「带哪些记忆」的决定权从人手上拿走，
  而且一旦默认覆盖就无法追回。X5 一律**预检 + 逐条可选**。
- **新开一张「知识表」支撑 X3 视角投影**：否决。既有证据账已有 `scope` / `knower` 两格，
  新开表就是第二套事实库，必漂。

## Acceptance criteria

九项都必须：

- **可复算读数**：每条给出命令与输出（写进证据页）；
- **三条铁纪律逐条自证**：不新增第二套事实库（数据源可点名 + 无新存储键）/ 不改 `WM_VERSION`
  （除非确实改数据结构，且须在正文写明理由）/ 不复制正文绕开 owner（摘要只用 id 与计数）；
- **只读面必须自证只读**：X1 / X2 / X3 / X4 / X7 五件要断言「操作前后既有槽位逐字不变」；
- **写入面必须有撤销或二次确认**：X6 / X8 / X9 三件逐条写清楚怎么撤；
- **至少一条真源码破坏负控制**，且**配原版对照**（只断破坏侧是假绿第二形）。

## Risks

- **X2 / X9 可能变成「先补内核」**：两件的内核都只有骨架。纪律：
  **开工第一天先读内核源码定能力边界**，若补内核超过预估一半工时，就在 `TODO` 里降级成
  「本期只交付只读面，写入面顺延」，不许硬做完成半截。
- **X5 跨对话存储位置未查清**：`memory-organs` 的存储是按对话/按角色，实测未确认。
  这是**必须先查清再动手**的一件，查不清就降级为「只导出不导入」。
- **X3 / X9 都涉及秘密**：本仓在秘密上有三刀历史（知识范围 / 正文剥离 / 知情名单方向纠正），
  任何一件新面碰秘密都必须**复用既有判定**，不许自己写一套「该不该给他看」。
- **X8 要真跑生成**：环境里没有 ST，真跑生成可能做不了。若如此，本条降级为
  「结构证明 + 手工仿真」，并在诚实边界写明 —— 不冒充「真机验过」。
- **本面九项与优化面 O2 / O8 都会碰记忆条目存取**：两边必须**同一口径**（软删/tombstone 与
  沿革链要能对上）。建议 O2 先落地，X1 再开工。
