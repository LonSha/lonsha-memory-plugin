# Agent Note: 记忆插件第四期拓展九项——从事实存储到有据的创作能力

Status: proposed

## Problem

2026-10-15 基线 `main@0f2f7fd` / v3.328.0。第三期的导入、年鉴、正史、旧事重现、视角和问答已有内核；不足不在“缺少这些名字”，而在受控算法是否能服务真实剧情、用户是否能完成确认、正常会话是否供应真实数据。

本期九项分两类：把既有预览底座闭合成用户能力（X1/X2/X3/X7），以及增加现有字段不能直接提供的工作流（X4/X5/X6/X8/X9）。前者明确是续建，不重复宣称“首次实现”。[优化九项](../../proposed/architecture/2026-10-15-product-optimization-v4.md)负责身份、质量、性能与真实供数；本篇负责新任务结果。所有条目为 proposed。

## Proposal

### M4-X1 · 可校订的分层导入与源资料更新（P1 / L）
- **现状证据｜实测+读码**：`lore-import.js::classify` 优先关键词判规则；“过去他必须每天服药，后来已经停药”被判 setting-rule；planApply 只产计划，changedSections 已有段落差分。当前不缺分类名，缺人工校订与实际导入旅程。
- **用户收益与增量**：同段混合设定/前史可拆分改类，确认角色映射后导入；资料更新只审改动段，保留人工决定，不误覆盖聊天已确认事实。
- **落点与依赖**：M4-O1/O5/O6；原生 memory-center 导入页复用 lore-import、PrequelSystem、fact-version、project-registry 的既有 owner。内容分类先规则+人工，模型建议为可选且需明示发送范围。
- **验收**：完成“导入→改类→同名映射→选入→保存→重开可查→源更新→只复审变更”；规则不冒充已发生，未选段不写；同源重复导入幂等；语义分类用混合段落人工抽查而非只验四类可达。
- **不做**：不新增通用内容 ETL 平台、不联网爬虫、不让手机只读桥直接改事实；原生确认与回执供 R4-X2 交接。

### M4-X2 · 面向读者的章节回顾与年鉴成稿（P1 / L）
- **现状证据｜读码**：`story-annual.js` 已有四要素、证据引用、草稿编辑和过期检测；belletristic 只是词表读数，不生成/改写可读文章；章节/摘要依赖需 O6 接到真实数据。
- **用户收益与增量**：从真实剧情生成可编辑的章节回顾，既有事件线也有人物变化；改正文不篡改记忆，重建受影响章节而非整本重写。
- **落点与依赖**：O6/O9，复用 SummarySystem、project-registry 和 narrative-generators 的模型通道；草稿按既有创作持久化方式保存，事实只以引用关联；手机 R4-X3 负责阅读编辑交互。
- **验收**：三章真实会话成稿、改一章源文只提示相关章过期；逐段检查重要事件、转折、原话对应来源；无剧透版不漏后续事实；未调用真实模型只能报告结构成稿，不报文风通过。
- **不做**：不再造摘要库、不只统计禁词就宣称去八股完成、不自动发布作品。

### M4-X3 · 正史选择真正进入下一卷（P2 / L）
- **现状证据｜读码**：`branch-canon.js` 的冲突按 collision/slot 机械匹配，选择/交接/撤销为纯计划；已有 branch-semantics、volume-continuation、project-registry 可承接持久化。当前不重新开发 merge 算法。
- **用户收益与增量**：选择结局后下一卷生成真正采用该结果；未选支线留在档案，不再夹进当前上下文。
- **落点与依赖**：O1/O6；原生正史选择页→既有分卷导入 owner→实际查询/注入消费。不能自动识别的语义冲突允许用户补“同一冲突位”，不把模型猜测当定论。手机 R4-X4 仅前端对照与交接。
- **验收**：选择→预览→确认→重启→新卷问答/生成五步完整；两个互斥结局仅选中者生效；本次撤销不删原分支或后来手工新增事实；重复确认不重复接续。
- **不做**：不重写分支存档、不替用户裁决最佳结局、不把 plan 的 applied 字段当真实已写。

### M4-X4 · 带消歧与条件继承的多轮记忆问答（P1 / L）
- **现状证据｜读码**：`planQuestion/askMemoryQuestion` 是单问句规划，不接前问语义状态；M3-X1 已有单次问答，不能作为新项再报。模糊代词、接续比较需要显式上下文。
- **用户收益与增量**：“她后来呢”“与上次相比”可沿用已确认的事件/人物/时点；不确定时给候选让用户选，而不是悄悄扩大范围。
- **落点与依赖**：O2/O3/O4；对话状态只保存结构化查询约束、选中实体/事件 ref 与 scope，复用现有查询 API 和实体解析，不存第二份答案事实。手机 R4-X1 提供聊天式界面，原生面也可用。
- **验收**：5轮追问、明确换人、两人比较、回到旧时点、切分支；每次展示继承/新设条件，歧义未决不产确定结论，取消不改前问；对照人工期望和未调参改写句。
- **不做**：不新增无限上下文代理，不把上一轮模型措辞当新证据，不跨会话暗中继承问题。

### M4-X5 · 同一事件的多方证词与争议档案（P2 / L）
- **现状证据｜读码**：knowledge-trace/perspective-card 已区分亲历、听说、误信；fact-version 有冲突状态；relation-history 关注人物关系。已有块不能直接回答“甲和乙对同一事件分别怎么说、为何暂不能下结论”。
- **用户收益与增量**：悬疑/群像中保留多方说法、来源链与证据强弱，作者可对照，角色只看到自己知道的说法；新证据出现时看清哪条说法被支持或推翻。
- **落点与依赖**：O1/O2，复用事件 ID、知识轨迹与事实冲突，增聚合投影和原生详情，不建立平行证词数据库；可选支持关系必须指向证据，不把三次转述算三份独立证明。手机 R4-X5 展示。
- **验收**：甲亲历、乙转述甲、丙反证三条；前两条共用来源不得算两份独立支持，未裁决说法均保留；揭密前后视角不同，撤回证据会更新争议状态。
- **不做**：不多数票裁真相、不增加虚构置信百分比、不把全知档案注入每个角色。

### M4-X6 · 梦境、假设、计划与现实的叙事层记忆（P2 / L）
- **现状证据｜读码**：memory-type 有9类事实、来源与冲突策略；secret/knowledge 能表达误信；narrative-pulse 可排除不可信情绪。但“事实类型”与“叙事是在梦里/假设中”不是同一轴，当前未见贯通提取→查询→摘要的独立层级旅程。
- **用户收益与增量**：梦到角色死亡不把现实角色写死；“如果搬走”不变成已搬走；仍能回答“梦里发生了什么”和“当初计划是什么”。
- **落点与依赖**：O2/O7；在既有提取/事实/摘要载体补受控 modality 与原文框架引用，不另建一套时间线。复用事实准入与时态，角色误信保留为角色认知而非现实真值；老数据不猜测批量重标。
- **验收**：现实/梦境/假设/尚未执行计划/引述五类及嵌套例；现实问答与生成不吃非现实结果，定向查询可以回看对应内容；计划在剧情落实后有明确事件关联，不因一句“决定了”自动完成。
- **不做**：不以关键词“梦”一票判定、不无限细分叙事层、不追溯改写无证据的旧记忆。

### M4-X7 · 旧事重现进入真实生成且由玩家控频（P1 / L）
- **现状证据｜读码**：`fated-recall.js` 已按地点/日期/物品/人物匹配，排序主要用 weight，宿主 _fatedRecallState 为实例内状态；候选供数缺口属 O6。当前可注入候选不等于生成管线实际用过，更不等于此刻应景。
- **用户收益与增量**：重返旧地时自然想起合适的一段旧事；可以“这次不提/少提这件事”，重开后不马上重复，也不把伤心场景硬塞喜事。
- **落点与依赖**：O6/O9，复用 recall-echo、注入预算 owner 与现有设置存储；默认提示，显式允许才自动注入。冷却按实际展示/使用落定，预览不消耗冷却；反馈只是呈现偏好，不删除历史事实。
- **验收**：从正常场景入口触发一次建议并实际进入允许的生成通道；预览/取消不算已用，重开/切回不重复轰炸；三类情绪场景人工评相关性，真实模型未验不报“自然”。
- **不做**：不建常驻提醒代理、不以触发键命中数代替叙事质量、不用情绪猜测修改历史。

### M4-X8 · 按下一幕任务生成精简记忆材料包（P2 / L）
- **现状证据｜读码**：getContinuityPack 偏分卷接续；召回、scene-book、关系、承诺、视角与 fated-recall 各自已有；当前缺“给下一幕写作任务选择一组互相一致材料”的统一产品输出。
- **用户收益与增量**：赴约重视地点/约定/参与者，重逢重视关系变化/共同往事；相同预算下少放泛泛事实，多保任务必须的信息。
- **落点与依赖**：O2/O3/O6/O9，可选消费 X7；在现有 projection/injection 路径增加按任务组织的只读材料投影，带来源和缺口，预算裁剪仍由既有 owner；手机 R4-X9 做预览选择。
- **验收**：同一库三种下一幕目标，材料差异可解释、关键约束齐全；相互矛盾的当前值不并列当真，未来/受限事实不进入；相同 token 预算下对照原召回，人工核相关性和必要信息保留。
- **不做**：不新造导演系统、不代写未发生剧情、不绕过原注入预算、不过度抽象成通用规划框架。

### M4-X9 · 资料与剧情分区的联合查证（P2 / L）
- **现状证据｜读码**：lore-import 保存段落来源和类别，evidence-query 主要查询账本；前史片段、正文资料、聊天事实来自不同 owner。现有资料导入不等于能回答“设定怎么说、剧情实际是否做到”。
- **用户收益与增量**：一次查询并排展示资料原句与剧情事实，识别设定/实际进展的差异；不会把参考小说中的事件当成当前会话已发生。
- **落点与依赖**：O2/O3/O5、X1；复用资料来源与现有查询，增加受控 sourceMode（仅剧情/仅资料/对照）和来源分区。只索引用户选择资料，原文从 owner 按需读取；R4-X8 的笔记仍是用户批注，不冒充原文或事实。
- **验收**：同名跨资料人物、未发生的设定事件、已发生但偏离设定的事件三例；答案分区引用，原文中后段也可查；撤除资料后不再引用其正文，历史来源显示失效。
- **不做**：不建设开放 RAG 服务、不联网扩搜、不默认将资料事实并入正史、不复制全文到每轮上下文。

## 批次与 owner

- 第一包“查得准、导得进”：X1/X4，与优化 O1/O2/O3/O4/O5/O6 配合。
- 第二包“读得懂、视角清楚”：X2/X5/X9，与 O9 配合。
- 第三包“剧情能力”：X3/X6/X7/X8；相互独立的项可并行，X8 先消费既有安全候选，不强等 X7 的自动注入。

跨仓成果不双计：M 侧完成事实/算法/确认写入，R 侧完成手机交互/阅读/创作入口。只读桥继续只读；原生确认页承接写入，若需要新交接协议必须先核真实能力并单独明确边界，不假设某个函数已存在。单装插件仍须能完成核心任务。

## 第五期接续说明（2026-10-20）

本篇保留第四期的理由、版本与验证边界；后续排序由[第五期X九项](2026-10-20-product-expansion-v5.md)接管。两篇部分重叠而非完全替代：已有模块继续复用，第五期按具体语义/真实消费缺口补闭环，并明确区分新能力；不得将本篇历史“当前缺口”直接复活成从零任务。

## Alternatives considered

- **扩大内部 API 菜单**：容易覆盖更多名词，但没有用户确认和真实数据仍不可用；先让既有机制完成任务。
- **每种需求新建账本**：有利于独立建模，却会重复事实/来源/撤回，长期一致性负担高；优先现有 owner 的类型补充和派生投影。
- **全部交给 LLM 自主决定**：表达弹性强，但分类、裁真相、写正史风险过高；模型仅提供可核对建议/表达，用户确认与事实约束由原链路执行。

## Acceptance criteria

九项各有明确增量、依赖、可观察的用户结果和不做范围。算法验收必须同时看内容是否正确、来源是否支持、是否适合当前角色/时点；自动化键面或自检行不是效果证明。真实模型未执行则保留待验，原生确认后的持久化须重开回读。

本轮只提交四份双仓计划及最小导航更新，不增加守卫/台账/发布工具占用36项名额。实施收口以用户旅程为单位，不以新增模块数、测试数或版本数为交付价值。

## Risks

语义分类与叙事层容易误判，需要人工可修、旧档保守兼容。逐事实无剧透与资料全文回源有存储/权限约束，不能用缺省公开绕过。模型调用必须走现有已配置通道；无可用模型时保留确定性预览，不暗用外部服务。
