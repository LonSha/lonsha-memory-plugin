# Agent Note: 第八期 LonSha 拓展创新——让记忆成为可探索、可演化、可参与的叙事介质

Status: proposed

## Problem

第七期已经让 LonSha 能处理口述史、传承、策展、角色访谈、关系修复、创作灵感、未完成约定、集体协商和可玩档案。第八期不再把这些主题换名重做，而是把已有记忆语义推进到“记忆本身可以成为一种可参与的媒介”：用户能感受记忆如何随季节、关系、重复行动和新证据演化，并能在不篡改事实的前提下创造新的叙事结构。

当前仓库已有 `symbolic-evolution`、`sleep-awaken`、`narrative-pulse`、`story-annual`、`era-inheritance`、`counterfactual-experiment`、`conditional-consequence`、`playable-archive-engine`、`collective-memory-deliberation` 等机制。真实缺口是这些机制之间仍然多为单次调用或单个语义出口，用户很难看到“一个记忆对象为什么在今天重新出现、它如何影响当前人物、它如何被重新解释”。第八期拓展重点是组合体验和可参与后果，不是新增无限账本。

## Proposal

### M8-X1 · 记忆季候：让长期主题有节律地浮现、沉寂和变调（P1 / XXL）

- **核心体验**：同一段经历在周年、关系变化、地点重访或相关新事件出现时，以不同强度和角度重新浮现；用户可以接受、延后、静音或追问。
- **真实落点**：组合 `narrative-pulse.js`、`story-clock-parse.js`、`sleep-awaken.js`、`echo-ledger.js`、`return-gate.js` 和 `recall-echo.js`；不以真实日期强行推进虚构世界，不用情绪值偷偷改权重。
- **独有机制**：浮现原因、上次处理、当前关联和未解释变化分列，记忆的“沉默”也有可解释状态。
- **验收**：同一主题在首次出现、被延后、相关事件发生后三种状态不同；静音不删除；重开保留处理选择；未授权或秘密内容不因季候浮现。

### M8-X2 · 意义地图：追踪地点、物件、语句和关系如何改变含义（P1 / XXL）

- **核心体验**：用户可以查看一个意象从“普通物件”变成“承诺象征”、再变成“冲突证据”的过程，并比较不同人物的含义。
- **真实落点**：组合 `symbolic-evolution.js`、`relation-history.js`、`meaning` 相关现有语义、`testimony-board.js`、`perspective-card.js` 和 `scene-book.js`。
- **区别于第七期**：不是展示一条意义变化日志，而是允许用户选择关键节点、标记解释来源、保留并列意义并把地图用于当前场景材料。
- **验收**：同一物件有三次意义变化、两名角色不同理解和一次反例；修订来源后只标记受影响节点；生成材料能区分事实、解释和待定；地图可从人物档案回跳。

### M8-X3 · 记忆天气与沉积：让一个世界拥有可感知但不虚假的长期氛围（P1 / XXL）

- **核心体验**：系统根据已发生事件、未决承诺、关系距离和资料变化，生成可解释的“世界天气”或沉积层，影响界面提示和场景建议，而不是直接替模型写情绪。
- **真实落点**：组合 `narrative-pulse`、`story-annual`、`relation-dynamics`、`commitment-ledger`、`material-pack` 和 RubyPhone 的场景桥；每个状态必须带来源和不确定性。
- **独有机制**：天气不是单一情绪值，而是“哪些主题正在变重/变轻、哪类事实缺失、哪些关系等待回应”的结构化投影。
- **验收**：至少四种天气来源可分别触发；缺来源、冲突、秘密和空盘互不混淆；关闭天气只关闭呈现不删除事实；材料计划可选择是否消费天气。

### M8-X4 · 记忆考古：通过碎片、空缺和错误线索重新理解一段经历（P1 / XXL）

- **核心体验**：用户以考古方式探索长期经历，先看碎片和缺口，再选择追问来源；系统不把“未找到”伪装成“没有发生”。
- **真实落点**：组合 `playable-archive-engine.js`、`evidence-query.js`、`lore-crosscheck.js`、`summary-provenance.js`、`knowledge-trace.js` 和 `perspective-preview.js`。
- **区别于第七期可玩档案馆**：可玩档案馆提供路线；本项新增证据缺口、错误线索、待确认假设和用户提出问题对路线的影响。
- **验收**：三条探索路径都能回到同一核心事实，但保留不同解释；错误线索不能进入正史；秘密未解锁不泄漏；用户退出后恢复探索位置；来源修订后路线标记需重看。

### M8-X5 · 记忆仪式：把确认、告别、纪念和重新开始变成有边界的互动场景（P1 / XL）

- **核心体验**：用户可以为一段关系、一件物品、一个项目或一个阶段创建仪式，邀请不同角色参与，留下各自的说法和后续承诺。
- **真实落点**：组合 `scene-book.js`、`relationship-repair-theater.js`、`unfinished-pledge-theater.js`、`testimony-board.js` 和 `event-chain.js`。
- **独有机制**：仪式不删除事实、不自动治愈关系；它只产生一组带参与者、可见范围、选择和后续影响的事件记录。
- **验收**：纪念、告别、重新开始三类仪式各有不同结果；角色可拒绝或缺席；用户重开能继续未完成仪式；仪式中的推断未确认前不进入长期事实。

### M8-X6 · 记忆驱动的角色成长剧：能力变化必须由经历和作品证明（P1 / XXL）

- **核心体验**：角色因为练习、失败、模仿、反思和关系影响改变做事方式；用户能看到变化来自哪些经历，而不是只看到一条经验值。
- **真实落点**：组合 `experience-rebuild.js`、`mentorship` 语义、`goal-tracker.js`、`craft`、`symbolic-evolution.js` 和 `character-agency-contract.js`。
- **区别于第七期师友共学**：第七期关注练习与师生关系；本项关注长期行为模式是否真的改变，以及改变何时被例外或失败推翻。
- **验收**：同一技能经历学习、失败、调整和迁移四段；角色不能声称没有证据的能力；新行为可回到作品/事件；回滚一段经历后成长状态标记受影响而非静默消失。

### M8-X7 · 多记忆视角剧本：同一事件可按不同知情路径演出（P0 / XXL）

- **核心体验**：用户选择主角、旁观者、未来回望者或资料研究者视角，看到同一事件的可知范围、误解和遗漏不同。
- **真实落点**：组合 `perspective-card.js`、`perspective-preview.js`、`knowledge-trace.js`、`narrative-layer.js`、`scene-orchestrator.js` 和 `story-annual.js`。
- **区别于第七期口述史/角色访谈**：第七期保存不同讲述；本项把视角差异编排成可演出的路径，且每次切换会重新计算可见材料，不只是换标题。
- **验收**：四种视角至少产生三处不同信息面；未知、推断、亲历和听闻分列；切换视角不改变事实；未授权秘密在任何路径不可见；演出可暂停、重开和回源。

### M8-X8 · 记忆共生协议：让 RubyPhone 的行动结果反过来改变记忆的使用方式（P0 / XXL）

- **核心体验**：手机里一次真实行动的结果会让 LonSha 记住“这个建议被采用/拒绝/失败/从未执行”，下一次材料计划和召回会因此更贴近用户。
- **真实落点**：通过既有 `phone-fact-bridge`、`generation-fact-receipt`、`memory-tools-api`、`injection-receipt` 和跨仓外供面实现；两仓分别保有自己的 owner，桥只传行动回执和引用。
- **独有机制**：不是把手机所有数据复制进记忆，而是把“建议—行动—结果—下次偏好”做成可审阅的闭环，失败结果也可被解释。
- **验收**：手机提议被接受、拒绝、超时、部分完成四态能分别进入记忆候选；用户可拒绝长期保存；下一轮材料计划能区分曾执行与仅提议；桥缺席时两仓各自可运行。

### M8-X9 · 时代接续剧：让跨时代传承通过具体物件、人物和选择发生（P1 / XXL）

- **核心体验**：进入新阶段时，用户不是阅读一份总摘要，而是通过继承的物件、未完成承诺、旧规则和新人物选择理解世界如何变化。
- **真实落点**：组合 `era-inheritance.js`、`lineage-heritage-tree.js`、`volume-continuation.js`、`institutional-memory.js`、`scene-book.js` 和 `playable-archive-engine.js`。
- **区别于第七期跨时代传承**：第七期建立跨时代数据承接；本项要求承接内容成为可选择、可失败、可被新一代拒绝或改造的连续体验。
- **验收**：至少三代/三阶段、两件传承物、一个被拒绝的旧规则和一条新解释；旧事实不被覆盖；新人物不知道不该知道的内容；断代处能显示缺失而不补写；重开可继续。

## Delivery sequence

- **A：重新感知记忆**：M8-X1、M8-X2、M8-X3。先把记忆的时间、意义和沉积变成可解释体验。
- **B：探索与仪式**：M8-X4、M8-X5。再让用户通过有限互动重新理解和处理经历。
- **C：人物与视角**：M8-X6、M8-X7。把成长和知情差异转成可演出内容。
- **D：跨项目闭环**：M8-X8、M8-X9。最后连接 RubyPhone 行动结果和跨时代接续，验证权限、撤销和分支隔离。

## Alternatives considered

- **继续增加新的记忆类型**：会让语义名词增长而用户体验不变；本期只组合已有类型成为可参与的行为。
- **把记忆变成分数、情绪值或游戏积分**：会压平事实、解释和视角；所有体验必须保留来源、未知和并列结果。
- **让模型自由生成缺失的过去**：短期顺滑但会破坏 LonSha 的核心可信度；空缺、冲突和未知必须可见。
- **把手机数据整库复制进记忆**：会破坏两仓 owner 和隐私边界；仅传用户可审阅的行动回执、引用和授权结果。

## Acceptance criteria

九项都必须消费真实记忆语义、提供用户选择并产生可持续的事件/观点/作品结果；结果必须区分事实、推断、草稿、角色视角和用户确认。静态演示、只生成一段文本、只增加一个导出 API 或只添加测试不能结项。

## Risks

叙事体验越丰富，越容易把演出误读成事实。每个演出结果都必须带来源、视角和采纳状态，默认不进入长期记忆；秘密和分支边界优先于连贯性，任何无法判定的内容都保持未决。
