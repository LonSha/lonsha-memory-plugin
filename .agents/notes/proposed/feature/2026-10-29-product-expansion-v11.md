# Agent Note: LonSha 第十一期拓展与独有机制计划
Status: proposed

> 与 [第十一期优化提升计划](2026-10-29-product-optimization-v11.md) 同批。**优化侧在清账（已建未用），拓展侧才谈新东西** —— 两条线并行的前提是：任何新机制**落地即接线**，不许再产出一批「加载了没人用」的模块（这正是 V9 的失败方式）。

## Problem

当前基线 `v3.426.0 / f907a80`。

V9 拓展侧（L9-X1 ~ L9-X9）点名的内核**全部已在仓里**（实测 41/41 存在），但其中 `symbolic-evolution`、`knowledge-network`、`relation-dynamics`、`institutional-memory`、`era-inheritance`、`character-agency-contract` 六个在宿主零引用。也就是说 **V9 拓展九项在代码上「有零件」、在产品上「不存在」**。

本期拓展不复述 V9 的名词表，只做两件事：

1. **把六个已建的拓展内核接成玩家真能进的门**（与优化侧 O1 同一动作，此处只规定产品形态与验收口径，不重复计数）；
2. **新增三件仓里确实没有的机制**，且每一件都锚在**已经验过的宿主能力**上（世界线纪元 / 证据裁决 / 卸载与重载），不另起炉灶。

## Proposal

### L11-X1 · 组织与制度记忆的真入口（接 `institutional-memory`）

- **真实现场**：`grep -c institutional-memory index.js` = **0**；模块在 `extra_js` 里、自检真跑、单测全绿。V9 的 L9-X5 写的是「学校 / 社群 / 家庭 / 工作组织能积累规则、惯例、创伤、传闻和制度变更」，产品面**一次都没进去过**。
- **产品形态**：面板增「组织」页：一张组织卡（章程 / 惯例 / 在册成员 / 传闻），每条记录标四类来源之一（个人知道 / 组织记录 / 公开规则 / 传闻）。制度变更走「提案 → 表决 → 生效 / 废止」，**旧版保留**（不删只标 superseded）。
- **独有机制**：**离开组织不自动遗忘**（人记得待过的地方），但**未公开记录不越权进入个人视角** —— 这两条方向相反，必须同时成立才是「制度记忆」而非「群聊记录」。
- **验收**：三类成员对同一制度知情范围不同；规则变更可追溯提案与表决；某成员退出后其已知内容仍在，但组织内部未公开记录对他不可见；把 `institutional-memory` 从 `extra_js` 摘掉 ⇒ 面板显示「不可用 + 原因」而非「0 条」。
- **规模**：**2 天**。

### L11-X2 · 意义演化的可解释面（接 `meaning-map` + `symbolic-evolution`）

- **真实现场**：`meaning-map` 在 `index.js` 有 1 处引用（取库口），`symbolic-evolution` = **0**。V9 的 L9-X2 要求「地点 / 物件 / 语句 / 关系从普通对象变成承诺象征、冲突证据或纪念物时，用户能看到节点、来源、人物差异和反例」，现在只有半个。
- **产品形态**：任一物件/地点详情页加「意义」抽屉：多义并列（同一对象可同时是「定情物」与「债务证据」）、每条带来源（哪一楼、谁说的）、人物差异对比、**反例单列**（「张三不这么看」）。
- **独有机制**：**删除一条解释只影响依赖它的节点，不抹掉其他人的理解**；意义**不写回事实 owner**（它是视角，不是事实）。
- **验收**：三次意义变化 + 两名角色不同理解 + 一次反例可完整回放；删一条解释后另一人的理解仍在；当前场景材料能区分「事实 / 解释 / 待定」。
- **规模**：**2 天**。

### L11-X3 · 世界线「前史」的作者工具（把 L11-O8 的读数变成可操作流程）

- **真实现场**：v3.426.0 的两处修法把口径改对了，但代价在 CHANGELOG 里如实写着：前史条目（楼层早于首跳登记）从 `native` 降为 `undecided`，出路是「**把首跳登记在第 1 楼**」。**这条出路目前只存在于文档与判据 M3 里，卡作者没有工具去执行它。**
- **产品形态**：世界线跳跃表编辑器上带一个「前史体检」：列出所有「楼层早于首跳」的记忆条目（key + floor + 当前判定 `undecided/epoch-asymmetry`），一键给两个可执行建议 —— ① 把首跳移到第 1 楼（改 `worldlineJumps` 第一行）；② 给这些条目补 `floor`。**不自动改卡数据**，只出建议与预览。
- **独有机制**：**「判不了」要被当成一种可修的状态，不是终局**。这与本仓「判不了 ≠ 否」是同一纪律的两端：不猜，但要给出补救路径。
- **验收**：体检能点名前史条目；应用建议 ① 后同批条目读数由 `undecided` 变 `blocked`（与 M3 判据一致）；不动卡数据时体检恒只读、零写入。
- **规模**：**1.5 天**。

### L11-X4 · 证据裁决的「影响回放」（接 `evidence-solver` + `fact-correction-bench`）

- **真实现场**：`evidence-solver` 在 `index.js` 有 2 处引用、`fact-correction-bench` 1 处 —— 都是**取库口级别**，没有面向用户的一次完整裁决流。V9 的 L9-O2 要求「知道一次裁决会影响哪些摘要、召回路线和未来注入」，这条**从未实现**。
- **产品形态**：冲突证据束上做一次裁决（采用 / 并列 / 待确认 / 撤回）后，出一张**影响回放卡**：受影响的摘要段落、受影响的召回路线、下一轮将注入的条目（引用而非正文）。
- **独有机制**：裁决**引用来源、不覆盖原始事实**；**撤销裁决后下游回到待定**，且未受影响的实体**不发生重算或串扰**（这是最容易被写成「全量重算」的地方）。
- **验收**：三条相互矛盾的年龄/地点/关系事实分别进四种裁决；撤销后下游回到待定；回放卡里不含任何秘密正文（沿用 v3.307.0 的秘密三面收口）。
- **规模**：**2.5 天**。

### L11-X5 · 跨仓回路：行动回执的可审阅链（接 `memory-symbiosis-bridge` + 兄弟仓）

- **真实现场（跨仓实测）**：兄弟仓 ruby-phone 的 `SubsystemOrchestrator` 有 **42 个公开方法，外部调用数全部为 0**（唯一入口 `advanceAutonomousLifeStep` 也零调用）；R10 声明的 18 个机制实例里只有 2 个（`notifications` / `moments`）被产品端真读。也就是说**上游这一侧要等的「行动回执」目前根本不会产生**。
- **产品形态**：本仓侧先把回路写好并有降级：`memory-symbiosis-bridge` 接受四种行动结果（接受 / 拒绝 / 超时 / 部分完成），每一笔记成「建议—行动—结果—下次偏好」的可审阅链；下游缺席时**如实报 `absent`**，不伪造回执。
- **独有机制**：**保存的是链，不是结论**；**失败和未执行同样是有意义的结果**（不许只记成功）；用户可**拒绝长期保存**（链不进长期记忆，只留本会话）。
- **验收**：四种结果分别进入候选；下游缺席时桥报 `absent` 且两仓仍可独立工作；用户拒绝长期保存后，下一轮材料里不再出现该链。
- **规模**：**2 天**（含跨仓面，但**不依赖兄弟仓先修**）。

### L11-X6 · 记忆的「卸载可逆」演练（本仓确实没有的一面）

- **真实现场**：本仓模块是 `extra_js` 经典脚本注入，v3.300.0 记录过「宿主从不加载 extra_js」的历史；但**没有任何一面演练过「模块被摘掉后插件还能不能活」**。当前 O1 要摘/删七个模块，**这恰好是最需要的安全网**。
- **产品形态**：一条 `npm run drill:unload`：随机/指定摘掉 N 个模块（默认 9 个：O1 的七件 + 两个边界模块），跑一遍启动 + 三条主路径（取数 / 召回 / 面板打开），断言**每一次都走降级而不是抛错**，并输出「谁缺席 / 谁降级成什么」。
- **独有机制**：**降级是被演练出来的，不是被声明出来的**。本仓大量 `_xxxLib()` 取库口带 `catch` 吞错，**吞了不等于降级对了** —— 演练要把「吞成空」与「降级成可用」区分开。
- **验收**：摘 9 个模块后台启动不抛错、主路径三条各给出可读的缺席原因；把某个 `catch` 改成 `throw` ⇒ 演练必须红（负控制）；全量 `npm test` 不吃这条（它是独立入口）。
- **规模**：**1.5 天**。

### L11-X7 · 「本版自己抓到的缺陷」自动归档

- **真实现场**：CHANGELOG 里每条版本都有一节「**本版自己抓到的缺陷**」（v3.426.0 是两处、v3.425.0 是四处），这些是**最有价值的教训**，但没有任何索引；想知道「哪一类错反复出现」只能全文 grep。
- **产品形态**：`tools/gen_defect_index.py` 扫 CHANGELOG，抽出全部「自己抓到的缺陷」条目，按**形态分类**（判据绿运行时错 / 锚点失配 / 假绿 / 夹具缺件 / 文档漂移 / 结构漂移），落 `docs/archive/defect-index.md`，并给每类一个计数。
- **独有机制**：**这是给下一版用的，不是给用户看的** —— 它的价值在于「同一形态出现过 N 次」这件事本身能阻止第 N+1 次。
- **验收**：索引含 v3.426.0 那两处；分类计数可复算（重跑得同一结果）；分类表写在文件头，新增类别要改表。
- **规模**：**1 天**。

### L11-X8 · 卡作者的「口径对照表」（世界线五键 + 纪元）

- **真实现场**：五键已进 `CARD_CFG_KEYS` + 有 UI 控件（v3.425.0 的 K 段判据把守），但**面向卡作者的文档不存在**。卡作者读 CHANGELOG 才知道 `worldlineJumps` 每行 `楼层:层标记`、才知道「只登记 jumps 不填 startFloor 会被自动推进」。
- **产品形态**：`docs/worldline-authoring.md`：五键逐条（含义 / 写法示例 / 不填会怎样 / 常见错法），含三张对照表 —— ① 条目形态 × 判定结果（有标记有楼层 / 只有标记 / 只有楼层 / 都没有）；② `epochAdvance.why` 四值含义；③ 保留者 `readerPolicy` 两值行为。
- **独有机制**：**每条口径都附一条可复算的判据名**（如「有标记 + 有楼层、无 startFloor ⇒ 按楼层反推」对应 L 段判据），让作者能自己验证而不是信文档。
- **验收**：文档里每个「会 / 不会」都被至少一条既有判据支撑；写错的示例必须能被判据抓出来（抽三条造错 → 红）。
- **规模**：**1 天**。

### L11-X9 · 记忆的「沉默状态」可解释（接 `memory-season` + `recall-echo`）

- **真实现场**：`memory-season` 在 `index.js` 有 1 处引用、`recall-echo` 无独立引用。V9 的 L9-X1 要求「沉默本身是有原因的状态，区分未处理 / 用户静音 / 没有关联 / 权限不可见 / 证据不足」，这条在代码里**没有一面聚合**。
- **产品形态**：某条记忆「为什么这轮没进来」的四问可查：① 没被召回（候选阶段就没进）；② 召回了被挡（`blocked` / `held` / `undecided` + 原因码）；③ 召回了被裁剪（预算不够，牺牲项具名）；④ 用户主动静音。
- **独有机制**：**静音不删除**（可随时重开）；**秘密不因周年浮现**；**「没进来」和「不存在」必须不同形**（这是本仓治过多次的错读数）。
- **验收**：同一主题首次出现 / 被延后 / 相关事件发生后三种结果不同；四问各给一条真跑读数；重开保留用户选择。
- **规模**：**2 天**。

## Delivery sequence

1. **先接线再谈新（X1 / X2 / X3）** —— 这三项都是「已建内核缺产品面」，做完 V9 拓展侧至少有一半真的存在。
2. **中段做闭环与回路（X4 / X5 / X9）** —— 裁决影响回放、跨仓回执、沉默可解释，都是「让用户能问为什么」。
3. **收尾做工具与安全网（X6 / X7 / X8）** —— 卸载演练要在 O1 摘删模块**之前**先有，但排在最后打包，因为它不产出用户可见功能。

## Alternatives considered

- **照 V9 的 L9-X1~X9 原样开工**：否决。V9 侧六个内核零消费，原样开工等于在同样位置再堆九个。
- **新增第十个「记忆类型」**：否决。本仓名词表已经过长；本期把已有意义压成「可解释面」而不是新类型。
- **把 X6 卸载演练写成守卫**：否决。它是**演练**（可复跑的破坏实验），不是门；写成门会让「降级对不对」变成「有没有写 catch」。
- **X5 等兄弟仓先修再开工**：否决。桥必须**缺席可用**（`absent` 如实报），这是本仓既有纪律；等下游等于把交付挂到别人的进度上（v3.20.4 的教训）。

## Acceptance criteria

九项都必须满足：

- 有**用户参与**（不是只出一个展示 API）、有**持久化的事件/观点/作品**、有**暂停或退出路径**、有**恢复入口**；
- 明确区分「事实 / 推断 / 演出 / 用户确认」四种边界，演出**默认不进入长期记忆**；
- 每一项上线当版即接线（`index.js` 真引用 + 面板可达 + 有真调用点），**不接受「先建内核、下版再连」**；
- 秘密与分支边界**优先于连贯性**；
- 诚实边界逐条如实写。

## Risks

- **叙事体验越强越容易被模型误读成事实**：所有演出对象必须带来源、视角、分支与采纳状态，默认不入长期记忆。
- **X6 会发现一堆假降级**：本仓大量取库口 `catch` 吞错，演练一跑很可能翻出「吞成空」被当成「降级成功」。这是**欠债显形**，按 O4 的三态口径修（`absent` / `empty` / `failed` 必须不同形）。
- **X7 是元工作**：必须严守「不占功能名额」，做完即止，不许扩成第二套治理系统。
- **跨仓节奏**：X5 只做本仓侧，下游修复由兄弟仓自己的计划负责；本仓不得因下游未修而积压。
