# Agent Note: lonsha-memory-plugin 第三期产品主线·拓展与新功能（九项）

Status: proposed

## Problem

> **2026-10-15 现状补注**：本篇是第三期提案快照，不再作为现行待办；十八项已在 v3.320～v3.328 获得代码承接（逐版映射见 PLAN.md 文首），但纯函数/出口交付不等于用户旅程闭合，故不批量改成 implemented。后续增量与排序见[第四期计划](2026-10-15-product-expansion-v4.md)，真实供数、原生确认和模型质量仍需分别验收。


用户要求把重心从守卫、台账和抬版转回项目主题。本计划基于 v3.319.0 / `b36c73a` 的代码侦察与定向探针，不沿用旧计划的完成勾选。这里交付的是计划，不是已实现功能；没有执行真实模型/浏览器体验验收。

## Proposal

共九项，编号 M3-X1 至 M3-X9。P0优先解决核心正确性，P1完成主要体验，P2扩展玩法；M/L为中/大工作包，不是工时承诺。每项必须产生玩家可见收益，不以新增门禁或多写文档作为完成标准。

### M3-X1 · 带证据的自然语言记忆问答（P1 / L）

- **现状与依据**：evidence-query 与 memory-tools-api 已能结构化查证；recall-explain 能解释召回。增量是多条件问题规划和证据合成，不是再造查询API。
- **具体增量**：把“谁答应了什么、后来怎样、为何改变”拆成受控查询；只基于许可结果生成答复，每个关键句可回源；无答案给缺口而非编补。
- **用户验收**：可回答跨两段证据的问题并引用各自来源；角色视角与作者视角结果不同；导出/手机显示不扩权；可不用额外模型走模板短答。
- **依赖与复用**：M3-O2/O3/O6/O9；R3-X2 负责手机体验。

### M3-X2 · 人物关系变化史与转折解释（P1 / L）

- **现状与依据**：已有relation-mutual/npc-ties/relationship-state与knowledge-trace；不是新增好感或关系账。
- **具体增量**：将双向关系随时间变化组织成轨迹，关联触发事件、各自认知与尚未解决的矛盾；支持指定时点比较，不把两人的看法平均成一个值。
- **用户验收**：用户能问“为何从信任变成怀疑”；每次转折有证据或标未明；同名不混；手机回忆册可消费许可投影。
- **依赖与复用**：M3-O3/O9；与 R3-X5 成对，记忆侧只负责事实轨迹。

### M3-X3 · 伏笔与因果链导航（P1 / L）

- **现状与依据**：seed-ledger 已有伏笔状态和MAX_OPEN=5；commitment-ledger/event-chain 已有约定与事件链。
- **具体增量**：把分散伏笔、承诺、事件结果连成可浏览依赖链：前因→触发条件→后果→未解问题；候选关系由用户或证据确认，推测边始终单列。
- **用户验收**：从某结果可追到原始铺垫；长期未解伏笔可按角色/章节找回；取消不是回收；不自动制造剧情因果。
- **依赖与复用**：M3-O4/O9；复用既有账，活跃位与历史目录分层而非无限放大MAX_OPEN。

### M3-X4 · 按角色与时点生成视角记忆卡（P1 / M）

- **现状与依据**：secret-ledger/knowledge-trace/knowledge-preview 已有边界与传播预演；当前增量是用于写作和生成的角色视角工作集。
- **具体增量**：选角色+时点生成“亲历/听说/误信/未知”的短卡；作者可对照两人信息差；请求使用角色许可面，作者观察不偷渡进角色上下文。
- **用户验收**：同场对话的两人拿到不同但有据的记忆；误信不写成世界真相；伪装未揭穿时卡面不露底；每次生成按需取，不存复制事实库。
- **依赖与复用**：M3-O3/O9；给 R3-O2/O3 用现有边界的聚合结果。

### M3-X5 · 设定资料与前史的分层导入（P2 / L）

- **现状与依据**：memory-books.js::PrequelSystem、world-rule类型与memory-package已有前史/规则/迁移底座。
- **具体增量**：导入作者提供的TXT/Markdown/世界书片段，分设定规则、前史事件、人物背景、仅供参考；预览实体映射/冲突/引用，再选择性确认；源更新只重审变更段。
- **用户验收**：设定不会冒充聊天中已经发生的事件；前史可查来源段；同名映射需确认；修订源资料不自动覆盖玩家已确认事实。
- **依赖与复用**：M3-O3/O8；复用前史/类型/包，不做通用联网爬虫与新数据库。

### M3-X6 · 支线结果的正史选择工作区（P2 / L）

- **现状与依据**：branch-semantics、project-registry::compareProjects、volume-continuation 已有分支对照/接续。
- **具体增量**：面向作者选择哪些事件结果成为后续正史；逐冲突选保留、并存或排除，生成可预览交接；保留分支出处和不被选中的历史。
- **用户验收**：两条支线结局不能自动同时成立；选择后新卷只带选中结局；秘密权限不扩大；可撤销本次接续，不改原分支。
- **依赖与复用**：M3-O9/O8；复用既有导入owner，不再写一套merge算法。

### M3-X7 · 章节回顾与可编辑故事年鉴（P2 / M）

- **现状与依据**：narrative-generators.js 已有日记/反思/大纲，project-registry 已有卷章，SummarySystem已有分层摘要。
- **具体增量**：按章节生成给玩家看的回顾：关键事件、人物变化、未了事项、精选原话；可切无剧透角色版/作者全知版；编辑的是作品草稿，不反写事实。
- **用户验收**：回顾可跳证据；原文改动提示对应段过期；作者改文风不污染记忆库；手机可排成日记或纪念页。
- **依赖与复用**：M3-O4/O9；复用摘要和创作底座，非再加摘要引擎。

### M3-X8 · 情境触发的旧事重现（P2 / L）

- **现状与依据**：已有narrative-pulse情绪线索、recall-echo及记忆召回；增量是面向人物关系/地点/日期的有限主动唤回。
- **具体增量**：重返地点、重要日子、重复物品等触发相关旧事建议；按角色身份、相关性、近期重复冷却选择；用户可关停或选“只给提示，不注入”。
- **用户验收**：同一地点能想起有来源旧事，但不是每次都重复；负面情绪不强制回忆好事；不会唤回角色未知内容或擅自写续剧情。
- **依赖与复用**：M3-O1/O3/O9；与 R3-X5/X9 相配，复用echo而非后台新常驻代理。

### M3-X9 · 局部重提取与原文对照编辑器（P1 / L）

- **现状与依据**：stm-ltm.js::reextract、repair-loop/repair-settle 与提取反馈已存在；缺口不是有无修复API，而是让用户选择范围并对照结果。
- **具体增量**：在原文中圈定楼层或段落，仅重提所选人物/事实类型；展示新增/保留/替换/冲突，逐项确认，按owner更新派生面；失败项可继续。
- **用户验收**：改一个人名不重建全库；未选范围不变；接受前不写；重试不重复事实；新旧正文并排且有出处，联动 M3-O7 的建议。
- **依赖与复用**：M3-O3/O5/O7/O8；复用现有repair与回读机制。

## Alternatives considered

- **继续强化守卫与台账**：能减少工程回归，但不能让用户聊得更像、记得更准。本轮不占任何名额，只修阻塞对应功能的最小问题。
- **把第二期未勾项重新列一遍**：成本低，但当前已有后续实现，容易重复造轮子。旧计划按历史快照保留，本轮以真代码和增量边界接管排序。
- **重建底座或新增一批独立App/账本**：可快速增加功能数量，却扩大分裂状态和维护成本。优先在现有入口、owner与存储上连成完整用户流程。

## Acceptance criteria

1. 每项先保留同场景基线，随后证明具体操作/输出改善；正确性用定向测试，体验用真浏览器/宿主，模型质量用固定预算与未参与调参的样本，三类证据不能互代。
2. 复用已有测试与审计；不为每个计划编号加一个守卫，不把通过测试数当产品收益。发布前按现有仓规执行所需检查；计划阶段只作相关检查。
3. 建议功能实现与体验打磨占实际投入至少80%，必要测试/接线/记录通常不超过20%；这是分配目标，不得为达比例省掉数据安全验证。安全故障可暂停，但不得顺势开启泛化审计项目。
4. 默认不增加LLM调用；确需模型的步骤按需、可取消、有预算预览。禁止未经确认执行真实外部发布/转账。
5. 现有会话/分支隔离、事实owner、备份与权限仍是约束；新接口应先服务真实消费点，再同步既有登记。

## Risks

- 本轮代码阅读和合成探针不等于用户实机故障发生率。除证据文档中的实测外，其余是以现实现限制为依据的改进提案；开工先跑目标旅程，不成立则缩减/撤项，不硬凑实现。
- 大工作包不可只交内核后就勾完成；需包含真实入口、操作、持久化/请求效果与对应验收。无服务或宿主能力须明确保留未验收项。
- 跨仓同名条目由owner区分：记忆侧负责事实/查询，手机侧负责展示/交互，不把同一次桥登记重复计成两个成果。
