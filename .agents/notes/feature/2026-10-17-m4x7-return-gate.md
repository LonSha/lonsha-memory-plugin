# M4-X7 · 旧事重现进入真实生成且由玩家控频(P1 / L)

状态:实施中(v3.345.0)

## 为什么要做(计划原文「现状证据 | 读码」逐条)

`fated-recall.js`(v3.328.0 · F 包 M3-X8)已交付四步:**情境 → 触发键 → 候选(相关性 + 冷却 +
知情面)→ 用户可选策略**,并明写「候选只到**建议重现 + 来源**为止,不产出任何正文」。
它答的是「此刻**为什么**该想起来」;它**不答**、也刻意不答的是三个下游问题:

1. **候选可注入 ≠ 生成管线真的用过**。`FR.suggest(...).injectable` 是一个**静态判断**
   (策略允许时给出一组可注入候选),但那一组从未被登记为「本轮**实际**进了允许的生成通道」——
   读数上「给了 12 条可注入」与「真用了 1 条」同形。
2. **没有生命周期**。`FR.markShown` 只记「展示过」(纯冷却用),但**预览**(玩家看到提示后
   决定「这次不提」)**与使用**(真的把这条写进本轮生成)两种动作在账上**完全没有分列**;
   于是「预览了一下就取消」会把冷却**误消耗**,下一轮想提也提不出来(计划「不做」区
   明写「预览不消耗冷却」)。
3. **没有控频强度档**。`FR.POLICY` 只有 off / hint-only / inject 三态,而**默认**是什么、
   「重开/切回会不会重复轰炸」没有闸。计划验收明写:「默认提示,显式允许才自动注入」
   「重开/切回不重复轰炸」。

## 本刀补的那一格

一个**只读 + 纯函数**的生成控频闸(内核 `return-gate.js`),把「建议」接到「真实生成通道」上:

- **生命周期三通道分列**:`preview`(预览)/ `shown`(展示)/ `used`(真用)。
  **冷却只按 `shown` / `used` 落定,`preview` 一律不消耗** —— 这是本刀立身之本。
- **控频强度档**:默认 `hint-only`;**只有显式 `inject` 才产出可注入面**;
  `off` 恒零。三态各自读数**不同形**。
- **重复轰炸闸**:同 (触发键, 旧事键) 在 `REPEAT_WINDOW` 楼内已 `shown`/`used` ⇒ 再问一律
  `held`(reason `repeat-window`),且**重开/切回**由宿主状态跨会话承载,内核只判。
- **反馈只是呈现偏好**:`feedback` 只记偏好(少提/不提),**绝不删除任何历史事件**
  (计划「不做」区明写「不用情绪猜测修改历史」)。
- **情绪只读**:情绪面一律只读不判(`emotionUsed:false`),内核**绝不**据情绪改写候选权重
  或强制重现(沿用 X6 / X5 的只读口径)。

## 落点与依赖(计划原文)

O6 / O9;**复用 recall-echo、注入预算 owner(`injection-router.js`)与现有设置存储**;
默认提示,显式允许才自动注入;冷却按实际展示/使用落定,预览不消耗冷却;
反馈只是呈现偏好,不删除历史事实。

## 不做(计划原文 + 本刀自加)

- 不建常驻提醒代理(纯函数、被问一次答一次,与 recall-echo 同规格);
- 不以触发键命中数代替叙事质量(内核不产任何「相关性分数」/ 百分比 —— 沿用 X5/X6 的
  `hasPercentKey` 自证);
- 不用情绪猜测修改历史(情绪字段只进读数);
- 不产正文(候选只到「建议 + 来源 + 闸态」为止);
- 不写库(写库仍由 index.js 的提取/事实账负责;本面 `writesNothing` 恒 true)。

## 与 X6 的显式区别(为什么不是把 X6 改一改)

X6 加的是**事实的叙事层轴**(reality/dream/hypothesis/plan/quote);X7 加的是**旧事重现
的动作生命周期轴**(preview/shown/used)。两者正交:一条旧事既有「它在哪一层」,也有
「它被提过没有、提了几次、这次算不算真用」。X6 的 `plan` 层答「打算做的事落实了没有」;
X7 的 `used` 通道答「这条旧事**此刻真的进了生成**没有」。不可合并。

## 诚实边界

- 真实 SillyTavern 宿主的 **UI 点击流**与**真实模型问答未跑**;
- 「三类情绪场景人工评相关性」属**人工评审**,内核只提供读数,不报「自然」;
- 老数据不猜测批量重标;真实模型未验不报「自然」。
