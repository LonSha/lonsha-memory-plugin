> **状态：排队中，非现行排序。** 现行唯一排序是第二十四期（见 `PLAN.md` 顶部）。

## 0. 证据状态与合并原因

`code_runner` / `package_proxy` 卡死、`grep` 在 linux 环境路径解析失效 ⇒ 本轮**无法检索消费点、无法跑 `npm test`、无法提交**。
因此本文件每条带状态：`【实读】`＝本轮真打开过该文件；`【待复核】`＝只有文件名/历史文档读数，**开工第一步必须复跑**。

O 与 X 合并成一份的理由同 R25：在无法 grep 的条件下分散三份，只会让未验证断言散落，更容易被当成已证。
本仓**已经吃过这个亏**：`vector-semantic-sparse-hybrid-retrieval.js` 里那个叫 `calculateSparseScore` 的函数
实际是 `includes` 命中比例，不是 BM25；而这个文件自己的尾注释写明它「真机上从未挂载成功」直到 v3.461.0
才从 ESM 改回 UMD —— 两条都是这轮实读才发现的（详见 R24 优化文档 §0）。

## 1. 本期判断：本仓最缺的是「落界」与「真消失」

本仓 408 个 `manifest.extra_js` 模块全部真加载、551 套判据、零消费已归 0、九座桥共用 `/lonsha-get trace` 出口。
**记录 / 展示 / 追踪这一层已经饱和**——再加一座桥不会让任何用户受益。

但有两个「终点」没做：

1. **记忆永远不真的消失**：有 tombstone（L13-O8 有测试），但 `find *purge*` 命中 **0** `【实读】`。
   用户说「忘掉这件事」，系统只是把它从视野里移开 —— 这在隐私上不成立。
2. **热/温/冷只落在台账里**：分层存储与压缩台账在盘，但「什么时候落界、落了之后用户看到什么、能不能撤回」没有产品面 `【待复核】`。

所以本期：**真删除**（做完整的三级链）+ **落界**（让分层与降级对用户可见、可撤回）。

## 2. 优化九项（L25-O1~O9）

| 编号 | 项 | 为什么它是最缺的（带状态） | 验收口径 |
|---|---|---|---|
| O1 | 真删除三级链：`mask` → `purge` → `purge_all` | `find *purge*` = 0 个文件；只有 tombstone `【实读】`。软删有、物理清无 ⇒「忘掉我」这句承诺不成立 | 三级语义各自可判：`mask` 只遮蔽（可还原）、`purge` 删实体但留审计占位、`purge_all` 连占位一起清；每级都有回执与前后条数 |
| O2 | 稀疏路补成真 BM25 | 现实现是 `includes` 命中比例，**无 IDF / tf 饱和 / 长度归一** `【实读全文】` | 补 IDF、tf 饱和、长度归一；与现比例分**对拍**（同一批 query 排名变化必须能逐条解释） |
| O3 | 召回延迟读数与增量索引 | 仓库无召回延迟读数（`【待复核】`）；`async-indexing-pipeline-debouncer.js` 从名字看是调度不是索引结构（未读全文） | 先出读数（P50/P95）再建索引；索引与线性扫描**结果逐条一致**；索引失效时 `degraded` 可见 |
| O4 | 写入幂等与并发收敛 | 同一条记忆重复写入、并发写同一键的收敛策略未成文 `【待复核】` | 重复写入不产双份（按内容指纹判）；并发写有确定的收敛顺序与回执 |
| O5 | 分层落界接线与撤回 | 分层存储/压缩台账在盘，缺「何时落界 + 用户可见 + 可撤回」`【待复核】` | 落界有回执（哪条、从哪层到哪层、为什么）；撤回后回到原层且检索命中一致 |
| O6 | 设置面信息架构 | `settings-ui.js` 5,787 行为唯一 UI，设置项继续线性增加 `【实读行数】` | 设置项可搜索、可分页签、可恢复默认；新增项不再拉长同一屏 |
| O7 | 诊断可读化 | 内部 code 直接抛给用户，无「这说明什么 / 该怎么办」`【待复核】` | 每个诊断码有一句人话 + 一个建议动作；未登记的人话不许上线 |
| O8 | 注入透明 | 每次注入的条目用户看不到、也问不到「为什么是这几条」`【待复核】` | 每轮注入列出「注入了哪几条 / 命中哪一路 / 为什么被选中」，缺理由即不合格 |
| O9 | 大文件拆分 | `worldline-memory.js` 72,480 B、`ledger-replay.js` 61,561 B、`snapshot-checkpoint.js` 37,769 B `【实读字节】` | 拆分后 `npm test` 全绿；行为逐条对拍一致；每条拆分给出「拆前/拆后行数」 |

## 3. 拓展九项（L25-X1~X9）

| 编号 | 项 | 为什么它是最缺的 | 验收口径 |
|---|---|---|---|
| X1 | 时间机器视图 | 有回放内核（`ledger-replay.js` 在盘），但没有「回到某条消息时刻，这个角色记得什么」的**视图** | 选一条消息 → 展示当时的记忆集；只读；与回放内核读数对得上 |
| X2 | 多视角记忆 | 同一件事各角色记的不一样，现在只有一份事实 | 同一事件能出两个角色视角，差异逐条列出；不合并、不裁决 |
| X3 | 共享事件 | 跨角色的世界级事实（战争结束、某人去世）无承载体 | 一条世界事实可被多角色引用；引用关系可查；撤销有回执 |
| X4 | 纠错闭环 | 用户纠错后，后续召回是否受影响无证据 | 纠错 → 下一次召回差异可见（带前/后命中对比）；纠错本身可撤回 |
| X5 | 记忆质量基准台 | 551 套判据里**没有一套是「给定对话 → 该召回命中」** `【实读文档读数】` | 一份金标准集 + 命中率/误召率读数；每次改动可复跑对比 |
| X6 | 多模态记忆 | 只有文本；图片/语音描述无法成为记忆 | 图片/语音可入记忆并参与召回；无宿主能力时 `absent` 不塌成空 |
| X7 | 关系图谱演化 | 有「谁出现过」，没有「关系怎么变的」 | 关系随时间可看（升温/降温/断裂）；每个状态变化可点到证据消息 |
| X8 | 冲突检测 | 两条记忆互相矛盾时系统沉默 | 检出冲突并标注（不自动改）；用户可二选一或并置 |
| X9 | 记忆摘要卡 | 用户问「你记得我什么」只能靠翻列表 | 一张可读的摘要卡（人、事、时间线、高频主题）；数字全部可点回源 |

## 4. 批次与依赖

- **A 批（终点先做）**：`O1`（真删除是承诺，不是功能）→ `O4`
- **B 批（准度）**：`O2` → `O3` → `X5`（没有基准台，`O2` 的改动无从判断好坏）
- **C 批（可见）**：`O7` → `O8` → `O6` → `X9`
- **D 批（记忆形态）**：`X1` / `X2` / `X3` / `X7` / `X8`
- **E 批（收尾）**：`O5` / `O9` / `X4` / `X6`

## 5. 本期纪律

1. **不许把「已登记的桥」再包一层**：本期任一项若最终只产出「一个可查接口 + 三态读数」，判为未交付。
2. **删除类操作一律先预览**：`purge_all` 必须有二次确认与条数清单，且**不可逆要明写**。
3. **`X5` 是本期唯一的度量入口**：任何「更快/更准」的断言必须引用它，不许凭手感。
