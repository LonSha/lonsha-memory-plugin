## 一、工程级认知清单（按重要度排序）

### A. 正文即数据库（baibai 最核心的世界观）

1. **时间标签锚点**（timeTag.ts）：主模型每楼正文前后输出 `<bbs_start>1988/9/29 21:30</bbs_start>`…`<bbs_end>`。标签**留在正文里**（发副 API、主模型续写都带着），仅用 ST 正则在显示层隐藏——真删会失同步。一箭三雕：① 一层楼起止双界（单一时间快照取不准）；② 摘要请求与新剧情生成并行时读同一权威时间，自然同步；③ 副任务（查询重写/摘要）的时间上下文免费获得。
2. **完整年份铁律**：数字日期必须带年份，否则跨年相对时间与周几不可靠；古风题材保留完整纪年（"庆历四年暮春·辰时三刻"），只要求"可定位到某刻"。
3. **正文旁注**（bbs_items/bbs_vars）：摘要后把本楼物品/变量净变动写进正文 `</bbs_end>` 之后——窗口内全文楼层天然可见，滚出窗口自然消失。"物品变动只在那段时间有用"的取舍，零维护成本。

### B. 事件溯源重放（apply.ts，2398 行）

4. **真源在楼层 extra（bbs_leaf），状态永远是派生数据**：deriveMemory 按楼层序 fold 出 items/plans/npcs/scenes/vars 全部状态。翻 swipe、删楼、隐藏楼，状态自动一致。与 lonsha v2.4/v2.7 同源但更深。
5. **确定性 id 三件套**：itemId/npcId 按规范化名、planId/detailId 按 leafId#序号、sceneId 按规范化路径——重放幂等、手动 op 可稳定引用、场景树父子关系由 id 前缀隐式成立（无需 childIds）。
6. **三态补丁语义**（patchText 家族）：undefined=未提供不更新 / null=明确清空（"场面彻底结束"）/ 值=规范化写入。缺局面一句话的局势卡更新视为无效，不当清空。
7. **重放顺序纪律**：同叶子内 items(add→update→remove)→plans(add→resolve→reopen→remove)，保证"先添加后操作"；plans.some(id 相同) return 防同叶子重放重复累加。
8. **age 锚点机制**：AI 只填 age，锚点 ageTime 由系统盖（=该叶子 storyTime），展示时按"锚点→当前时间"推算——时间跳跃自动长岁，AI 永不算错年龄。
9. **互斥位**：carried=true 清 location（随身物品无存放地）；NPC follow 同构。即时层（outfit/condition）给即覆盖，档案层（desc）实质变化才动。
10. **截断重放** deriveMemory(chat, upToExclusive)：查询重写快照的基石。番外楼（bbs_omit）不参与重放（lonsha SF5 同源）。

### C. 森林摘要与最小拆解选择（select.ts，纯函数零依赖可单测）

11. **森林结构**：L0 叶子（挂消息 extra）+ L1/L2 压缩节点（childIds 引用下层）。
12. **最小拆解算法**：为每个合格叶子选**最高的、能整体代表它的节点**（省 token）；否则降级逐子递归。
13. **完好性（intact）判定**：childId 悬空（翻 swipe→叶子失效）则压缩节点不完整——它的文本嵌着失效页的旧叙事，会与当前正文冲突；受影响链路拆到叶子层，旁支完好子节点整条保留。memoized + 防环占位。
14. **失活≠删除**：节点失活只是"当前不注入"，翻回原页自动复活。

### D. 多槽位注入架构（inject.ts）

15. **四槽位**：HISTORY D9999（顶部）/ STATE D1-D2 动态 / TIMETAG D0（最贴近下一条回复的最强指令）/ LEGACY key 永远注空串（防升级残留）。
16. **状态深度动态解析**：最新 AI 楼已有有效摘要→状态含它，D1；还没有→D2。状态永远贴着最新剧情。
17. **注入开关依赖链**：场景关→NPC/物品随之不注入（在场判定依赖场景树）。
18. **变量块绝不注入 rule**：变化规则含 set/assign 命令语法，主模型看到会误以为该在正文输出命令；只注入"含义"（是什么），明确框定只读、严禁复述。
19. **MEMORY_BRIEFING_NOTE/END 首尾框定**：防主模型把状态快照当输出模板（正文后跟吐一份状态）。
20. **NPC 四档注入**：主要角色（important 永远置顶+即时状态面板）/ 在场（全量）/ 同区域（留性格防临时登场 OOC，砍外貌/状态）/ 不在场（名+性别+称谓头+title）。**性别所有档都发**（把亲哥写成陌生人同级致命）；称谓头取 relation 第一逗号前、≤12 字，超长说明 AI 没按"称谓在前"写→放弃。
21. **物品两组**：可达（随身/存放地落在当前地点或祖先链）全量 vs 他处寄存（名+数量，"回到对应地点才有完整信息"）。
22. **oneLine 压平**：值内换行会丢"- "前缀、破坏注入结构误导 AI；UI 可软换行，注入必须压平（trim 拦不住中间换行）。
23. **生成与使用解耦**：叶子对所有楼层提前生成，但只有所在消息被隐藏（is_system）才注入顶替原文——仍在保留窗口发全文的楼层不注入，避免重复。
24. **时间双渲染器分叉**：主对话注入带相对时间（【(昨天·周三) 绝对时间】），副任务复用 renderHistoryNodes 不带（截止点/参照点不同，刻意分叉）。总结节点跨时段→起止两端各自相对同一 now，不用单个"昨天"代表整段。

### E. 向量召回管线（vector/，1927 行）

25. **双 hash 分层对账**：docHash（摘要文本）变才重 embed；payloadHash（全文/时间）变走轻量 payload 更新。同文本不重复 embed——"边玩边索引"不卡的关键。
26. **查询重写**：小模型把当前剧情重写成 INTENT + ≤6 条检索 Q（各 ≤220 字），各自 embed→多路检索→RRF 融合；INTENT 兼作 rerank query。上下文=历史摘要+最近窗口全文+状态快照（deriveMemory 截到第一个无叶子楼，只含滚出窗口的 items/plans/主角）+用户输入。
27. **fetchWithTimeoutRetry 语义**：超时/网络/5xx/429 重试；4xx 直接返回交调用方（重试无意义）；**外部取消（用户中止生成）立即抛绝不重试**——lonsha SF1 可补强此语义。
28. **VectorStore 抽象**：后端 baibaoku / 本地 IndexedDB 同名同签名透明降级；bundle（跨聊天快照）后端独占，不在时 carryover 自跳过=正确降级行为。
29. **召回调试快照**（debug.ts）：上次召回各阶段中间结果 reactive 快照供 UI 面板，失败/降级也记录并写明 status——"坏了有人知道吗"的工程答案，lonsha v3.0 SD 的向量版。
30. **召回缓存**：localStorage 键 + 索引素材变化即失效；注入深度 normalize 只收非负整数，非法回 D0。

### F. 跨聊天继承（carryover.ts）

31. **种子叶子模式**：合并历史摘要=种子叶子 text；当前状态编码成**全量 add delta**挂 #0；新对话靠现成重放管线（空白起步 fold）还原——无需任何特殊载体。
32. 向量 bundle 快照 hash 累加写 metadata，新对话可召回源聊天旧剧情。

### G. 提示词资产（prompts.ts）

33. **极严筛选纪律**：物品/NPC/生活细节"极严筛选"、场景"默认不记"——记录越少越准，宁缺勿滥。
34. **未了结 + 近期已了结双注入**：防 AI 把刚了结的计划当未完成再推进/重复记录。
35. 批量摘要逐楼输出 + thinking checklist + prefill 强制。

### H. 迁移（migrate.ts）

36. **快照→增量折叠**：Horae 逐层快照按楼序 fold 出最终态，整包一个 add-delta 挂最后一片叶子（避免逐层重放重复累加）；computeMigrationPlan 只读预览供 UI 启停。

## 三、差异大、待评估项

1. **正文时间标签锚点**：baibai 最大胆的设计，要求主模型每楼输出标签。lonsha 若采纳=生成协议变更（用户可见正文带标签，显示层正则隐藏）。收益极大（并行摘要时间同步、起止双界），侵入性也大。**最值得单独立项评估**。
2. **结构化状态重放**（items/plans/npcs/scenes 四大实体 + 变量命令）：lonsha 是自由文本摘要路线。混血方案：只给物品做确定性 id 重放（lonsha 已有物品台账 itemLedger，可升级为 delta+确定性 id）。
3. **森林多级压缩**（L1/L2 + 最小拆解选择）：lonsha 卷摘要平铺。若未来上下文压力大再评估。
4. **向量召回全套**（重写/RRF/rerank/双hash对账）：依赖外部 API 与后端，lonsha 定位是零依赖插件，成本收益需用户定夺。
5. **carryover 种子叶子**：lonsha 有类似"卷摘要继承"机制，种子 delta 编码思想可参考。

## 四、最重要的认知

**baibai 与 shujuku 是两种哲学：shujuku 是"每个功能配一个防御"（纪律型），baibai 是"让正确成为唯一可能"（结构型）。**

- shujuku 防数据坏：sanitizer、锁、修订号、错误规则库——相信数据会被污染，处处设卡。
- baibai 让数据**根本不可能坏**：状态不是存出来的而是重放出来的（翻 swipe 自动一致）；时间不是推断的而是正文事实（并行摘要自动同步）；年龄不是 AI 算的而是锚点推算的（永不算错）；注入顶替由"消息被隐藏"这个事实驱动（永与上下文一致）。**它把一致性从"运行时检查"挪到了"数据结构"里。**

对 lonsha 的启示：v2.4 事件溯源已踏上 baibai 路线，下一步不是加更多校验代码，而是**把更多状态从"存储态"改成"重放态"**（如物品台账从独立存储改为楼层 delta 重放），并借鉴"确定性 id + 三态语义"两个最小可行机制。

## 五、下一步借鉴优先级（建议）

1. **物品台账升级**：itemLedger 独立存储 → 楼层 delta + 确定性 id（ itemId 按规范化名）+ 三态补丁语义。改动小、收益直接（翻 swipe 一致性免费获得）。
2. **LEGACY 槽位清空模式**：改名/升级后旧 key 注空串防残留注入，一行代码级防御。
3. **fetchWithTimeoutRetry 补强**：外部取消信号绝不重试语义（SF1 增强）。
4. **注入 token 估算面板**：estimateTextTokens（bytes/3.35 口径）给用户直观量级。
5. **未了结/已了结双注入**：反思系统 ReflectionSystem 可借鉴"近期已了结"防重复推进。
6. **正文旁注**（若采纳时间标签后的第二阶段）：物品净变动写正文，滚出窗口自然消失。
7. 时间标签锚点：单独立项评估（收益/侵入性都最大，需用户决策）。
